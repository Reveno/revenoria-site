# Резервування шлюзу за замовчуванням за допомогою HSRP

> [!abstract] Пов'язана лекція
> [[courses/computer-networks/lectures/07-stp-ahrehatsiia-kanaliv-ta-qos|Лекція 7. STP, агрегація каналів та QoS]], [[courses/computer-networks/lectures/15-statychna-marshrutyzatsiia|Лекція 15. Статична маршрутизація]]. Ви налаштовуєте протокол HSRP, щоб відмова одного маршрутизатора не залишала клієнтів без шлюзу.

## Навіщо ця робота

Усі комп'ютери підмережі мають один шлюз за замовчуванням. Якщо цей маршрутизатор вийде з ладу, жоден із них не зможе вийти за межі локальної мережі, навіть якщо поруч стоїть справний резервний маршрутизатор. Клієнти не вміють самі переналаштувати шлюз. Протокол **HSRP** вирішує це: два маршрутизатори розділяють одну **віртуальну** IP-адресу, яку клієнти використовують як шлюз. Один маршрутизатор активний і відповідає за цією адресою, другий очікує; при відмові перший його заміняє за секунди.

У лабораторній ви налаштуєте HSRP, перевірите, що клієнти не помічають відмови, і розберете, як керувати вибором активного маршрутизатора.

## Мета

Навчитися налаштовувати HSRP між двома маршрутизаторами: віртуальна адреса шлюзу, пріоритети, режим preempt, перевірка ролей і спостереження перемикання при відмові.

Після заняття ви повинні вміти:

- налаштовувати групу HSRP та віртуальну адресу;
- керувати вибором активного маршрутизатора пріоритетом і preempt;
- читати вивід show standby brief;
- перевіряти безперервність зв'язку при відмові;
- пояснювати роль віртуальної MAC-адреси;

## Обладнання та програмне забезпечення

- Комп'ютер із Cisco Packet Tracer 8.x (безкоштовне завантаження з netacad.com після реєстрації в Cisco Networking Academy).
- Файл-заготовка не потрібен: топологію ви будуєте самостійно за схемою нижче.
- Ключові пристрої моделі: два маршрутизатори 2911, комутатор 2960, комп'ютер, сервер.

## Теоретична частина

**Як працює HSRP.** Маршрутизатори групи обмінюються повідомленнями Hello (кожні 3 с). Той, у кого найвищий пріоритет, стає **Active** і відповідає на ARP-запити віртуальної адреси віртуальною MAC-адресою `0000.0C07.ACxx` (xx номер групи). Другий стає **Standby**. Якщо Hello від Active зникають на час hold (10 с), Standby перебирає ролі. Режим **preempt** повертає роль найвищому за пріоритетом маршрутизатору, коли він знову стає доступним.

## Хід роботи

### Крок 1. Налаштуйте адреси й маршрути

Налаштуйте інтерфейси за таблицею. Обидва маршрутизатори безпосередньо підключені і до мережі клієнтів, і до мережі сервера, тому додаткова маршрутизація не потрібна. Щоб відмова не ламала зворотний шлях, HSRP налаштовують **з обох боків**: клієнти використовують віртуальний шлюз 192.168.10.254, а сервер 172.16.0.254.

> [!tip] Якщо сервер використовує адресу реального маршрутизатора як шлюз, то після відмови цього маршрутизатора відповіді сервера не повернуться клієнту.

### Крок 2. Увімкніть HSRP

Група 1, віртуальна адреса 192.168.10.254. R1 отримує вищий пріоритет та preempt.

```
! R1
interface gi0/0
 ip address 192.168.10.2 255.255.255.0
 standby version 2
 standby 1 ip 192.168.10.254
 standby 1 priority 110
 standby 1 preempt
 no shutdown
interface gi0/1
 ip address 172.16.0.1 255.255.255.0
 standby version 2
 standby 2 ip 172.16.0.254
 standby 2 priority 110
 standby 2 preempt
 no shutdown
! R2
interface gi0/0
 ip address 192.168.10.3 255.255.255.0
 standby version 2
 standby 1 ip 192.168.10.254
 standby 1 priority 100
 standby 1 preempt
 no shutdown
interface gi0/1
 ip address 172.16.0.2 255.255.255.0
 standby version 2
 standby 2 ip 172.16.0.254
 standby 2 priority 100
 standby 2 preempt
 no shutdown
```

### Крок 3. Перевірте ролі

Виконайте `show standby brief` на обох маршрутизаторах.

![[attachments/ksm-pt23-step3.svg|820]]
*Крок 3. R1 Active, R2 Standby. Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 4. Змоделюйте відмову

На PC1 запустіть безперервний пінг `ping -t 172.16.0.100`. На R1 вимкніть інтерфейс `shutdown` і простежте: втрачається лише кілька пакетів, потім зв'язок відновлюється через R2.

![[attachments/ksm-pt23-step4.svg|820]]
*Крок 4. Короткий збій, потім R2 стає Active (Standby невідомий, доки R1 вимкнено). Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 5. Поверніть R1 і перевірте preempt

Увімкніть інтерфейс R1 (`no shutdown`). Завдяки `preempt` R1 повертає роль Active (затримка кілька секунд).

```
show standby brief
```

## Завдання для самостійного виконання

Налаштуйте відстеження зовнішнього інтерфейсу: `standby 1 track gi0/1 20`. Вимкніть Gi0/1 на R1 і покажіть, що пріоритет R1 знизився до 90, тому Active став R2, хоча сам R1 живий. Поясніть, для чого це потрібно.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базової топології |
|---|---|
| 1 | група 1, віртуальна 192.168.10.254, R1 пріоритет 110 |
| 2 | група 5, мережа 10.0.0.0/24, віртуальна 10.0.0.254 |
| 3 | аутентифікація `standby 1 authentication md5 key-string <ключ>` |
| 4 | відстеження інтерфейсу track Gi0/1, зменшення 30 |
| 5 | таймери `standby 1 timers 1 3` |

## Типові помилки

- Не виконати `copy running-config startup-config`: після перезавантаження налаштування зникнуть.
- Не підписати пристрої й порти: у звіті неможливо зіставити скриншот зі схемою.
- Вказати як шлюз клієнтів адресу реального маршрутизатора замість віртуальної.
- Налаштувати різні номери груп чи версії на двох маршрутизаторах.
- Не ввімкнути preempt і дивуватися, що роль не повертається.

## Вимоги до звіту

Звіт подається без титульного листа й містить: тему й мету; схему топології зі своїми підписами; таблицю адресації; повний перелік введених команд; скриншоти ключових кроків із Packet Tracer (кожен із видимим ім'ям пристрою та часом); відповіді на контрольні питання; висновки. Файл проєкту `.pkt` додається окремо.
