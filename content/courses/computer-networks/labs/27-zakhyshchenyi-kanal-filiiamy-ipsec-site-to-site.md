# Захищений канал між філіями: IPsec site-to-site на маршрутизаторах

> [!abstract] Пов'язана лекція
> [[courses/computer-networks/lectures/20-vpn-ipsec-ta-wireguard|Лекція 20. VPN IPsec та WireGuard]]. Ви налаштовуєте IPsec VPN між двома маршрутизаторами через мережу «провайдера» й перевіряєте, що трафік філій шифрується.

## Навіщо ця робота

Філії хочуть спілкуватися, але інтернет не довіряє нікому. IPsec вирішує це на рівні маршрутизаторів: кожний шифрує пакети, що йдуть до іншої філії, і розшифровує ті, що приходять. Користувачі нічого не помічають, а програми працюють як у одній мережі.

У лабораторній ви самі пройдете всі етапи: узгодження параметрів (ISAKMP), параметри шифрування (transform-set), перелік трафіку, що підлягає шифруванню (ACL), прив'язка до інтерфейсу (crypto map). Налаштування одне з найскладніших в курсі, але на ньому добре видно логіку захищеного каналу.

## Мета

Навчитися налаштовувати IPsec site-to-site VPN на маршрутизаторах Cisco: ISAKMP-політику, ключ, набір параметрів шифрування, ACL цікавого трафіку, crypto map, а також перевіряти стан тунелю й шифрування трафіку.

Після заняття ви повинні вміти:

- налаштовувати політику ISAKMP і попередньо розподілений ключ;
- створювати transform-set і crypto map;
- визначати трафік для шифрування за допомогою ACL;
- перевіряти стан тунелю командами show crypto;
- пояснювати відмінність фаз IKE;

## Обладнання та програмне забезпечення

- Комп'ютер із Cisco Packet Tracer 8.x (безкоштовне завантаження з netacad.com після реєстрації в Cisco Networking Academy).
- Файл-заготовка не потрібен: топологію ви будуєте самостійно за схемою нижче.
- Ключові пристрої моделі: два маршрутизатори 2911 із ліцензією securityk9, маршрутизатор ISP, два комп'ютери.

## Теоретична частина

**Фази.** *Фаза 1 (ISAKMP/IKE)*: пристрої автентифікують один одного (тут за попередньо розподіленим ключем) та створюють захищений канал керування. *Фаза 2 (IPsec)*: створюються тунелі для даних із параметрами transform-set (шифрування ESP, цілісність). Трафік вибирається ACL («цікавий трафік»).

**Важливо.** ACL на обох кінцях мають бути **дзеркальними**, а параметри політик збігатися. У Packet Tracer доступний протокол IKEv1 і обмежений набір алгоритмів (зазвичай AES, SHA, група 2); у реальних мережах використовують IKEv2, групи 14 і вище, сильніші алгоритми.

## Хід роботи

### Крок 1. Налаштуйте адреси й маршрути

На R1 та R2 маршрут за замовчуванням до ISP; ISP знає лише підключені мережі. Переконайтеся, що R1 пінгує R2 за публічними адресами (198.51.100.2 ↔ 203.0.113.2), а приватні мережі між собою ще не бачать одна одну.

```
! R1
ip route 0.0.0.0 0.0.0.0 198.51.100.1
! R2
ip route 0.0.0.0 0.0.0.0 203.0.113.1
```

### Крок 2. Увімкніть ліцензію безпеки

На маршрутизаторах 2911 у Packet Tracer потрібна технологічна ліцензія.

```
license boot module c2900 technology-package securityk9
! підтвердити yes, потім
copy running-config startup-config
reload
```

> [!tip] Після перезавантаження перевірте `show version`: у списку технологій має бути `securityk9` зі статусом «Technology Package License Information».

### Крок 3. Налаштуйте ISAKMP (фаза 1) на R1

Політика й ключ для сусіда R2. Ключ нікому не показують; у звіті наводять шаблон.

```
crypto isakmp policy 10
 encryption aes 256
 hash sha
 authentication pre-share
 group 2
 lifetime 86400
crypto isakmp key <СПІЛЬНИЙ_КЛЮЧ> address 203.0.113.2
```

### Крок 4. Налаштуйте IPsec (фаза 2) на R1

Набір шифрування, ACL цікавого трафіку та crypto map на зовнішньому інтерфейсі.

```
crypto ipsec transform-set TS esp-aes 256 esp-sha-hmac
access-list 110 permit ip 192.168.10.0 0.0.0.255 192.168.110.0 0.0.0.255
crypto map VPNMAP 10 ipsec-isakmp
 set peer 203.0.113.2
 set transform-set TS
 match address 110
interface gi0/1
 crypto map VPNMAP
```

### Крок 5. Налаштуйте R2 дзеркально

На R2 ті самі політика й набір, ACL дзеркальний (джерело та призначення міняються місцями), peer 198.51.100.2.

```
crypto isakmp policy 10
 encryption aes 256
 hash sha
 authentication pre-share
 group 2
 lifetime 86400
crypto isakmp key <СПІЛЬНИЙ_КЛЮЧ> address 198.51.100.2
crypto ipsec transform-set TS esp-aes 256 esp-sha-hmac
access-list 110 permit ip 192.168.110.0 0.0.0.255 192.168.10.0 0.0.0.255
crypto map VPNMAP 10 ipsec-isakmp
 set peer 198.51.100.2
 set transform-set TS
 match address 110
interface gi0/1
 crypto map VPNMAP
```

### Крок 6. Запустіть тунель і перевірте

З PC1 виконайте `ping 192.168.110.10`: перші пакети можуть загубитися, доки узгоджуються параметри. Потім перегляньте стан.

## Завдання для самостійного виконання

У режимі Simulation відстежте пакет від PC1 до PC2: на ділянці R1 → ISP → R2 його вміст зашифровано (у деталях PDU видно ESP, а не ICMP). Поясніть, чому ISP не може прочитати вміст і що він бачить.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базової топології |
|---|---|
| 1 | філії 192.168.10.0/24 ↔ 192.168.110.0/24, AES-256, SHA |
| 2 | філії 10.1.0.0/24 ↔ 10.2.0.0/24, AES-128 |
| 3 | три філії: додати R3 і другий тунель |
| 4 | час життя ISAKMP 3600 с, фаза 2 1800 с |
| 5 | додати захист ACL на ISP, що дозволяє лише ESP та ISAKMP |

## Типові помилки

- Не виконати `copy running-config startup-config`: після перезавантаження налаштування зникнуть.
- Не підписати пристрої й порти: у звіті неможливо зіставити скриншот зі схемою.
- Не дзеркальні ACL на кінцях: тунель не будується.
- Різні параметри ISAKMP на сторонах.
- Не застосувати crypto map до зовнішнього інтерфейсу.
- Не ввімкнути ліцензію securityk9.

Звіт подається без титульного листа й містить: тему й мету; схему топології зі своїми підписами; таблицю адресації; повний перелік введених команд; скриншоти ключових кроків із Packet Tracer (кожен із видимим ім'ям пристрою та часом); відповіді на контрольні питання; висновки.
