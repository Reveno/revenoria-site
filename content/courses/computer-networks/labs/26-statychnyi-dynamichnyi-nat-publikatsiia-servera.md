# Статичний і динамічний NAT та публікація сервера

> [!abstract] Пов'язана лекція
> [[courses/computer-networks/lectures/14-dhcp-nat-pat-ta-spysky-dostupu-acl|Лекція 14. DHCP, NAT-PAT та списки доступу ACL]]. Ви налаштовуєте різні види трансляції адрес: статичну для сервера, динамічну з пулом і з перевантаженням.

## Навіщо ця робота

Приватні адреси не маршрутизуються в інтернеті, тому для виходу назовні потрібен NAT. Але NAT буває різним, і кожен вид має своє призначення. **Статичний** прив'язує приватну адресу до публічної один до одного (потрібен для серверів, до яких звертаються ззовні). **Динамічний** видає публічні адреси з пулу на час сеансу. **PAT** (перевантаження) дозволяє багатьом вузлам ділити одну адресу, розрізняючись портами.

У лабораторній ви налаштуєте всі три види на одному маршрутизаторі й перевірите кожен: вихід клієнтів, доступність вебсервера ззовні й таблицю трансляції. Тут стає зрозумілим, чому сервер «ззовні» бачать за публічною адресою, а клієнти на моніторі інтернету виглядають по-різному.

## Мета

Навчитися налаштовувати статичний NAT для публікації сервера, динамічний NAT із пулом адрес і PAT на інтерфейсі, перевіряти трансляції й діагностувати проблеми.

Після заняття ви повинні вміти:

- налаштовувати статичний NAT (ip nat inside source static);
- створювати пул публічних адрес і налаштовувати динамічний NAT;
- налаштовувати PAT (overload);
- позначати інтерфейси inside та outside;
- читати таблицю трансляції;

## Обладнання та програмне забезпечення

- Комп'ютер із Cisco Packet Tracer 8.x (безкоштовне завантаження з netacad.com після реєстрації в Cisco Networking Academy).
- Файл-заготовка не потрібен: топологію ви будуєте самостійно за схемою нижче.
- Ключові пристрої моделі: маршрутизатор 2911, маршрутизатор ISP, комутатори, два комп'ютери, вебсервер, зовнішній клієнт.

## Теоретична частина

**Види NAT.** *Static*: 1:1, постійна відповідність. *Dynamic*: клієнт отримує вільну адресу з пулу на час сеансу, 1:1 тимчасово; коли пул вичерпано, нові клієнти отримують відмову. *PAT/overload*: багато-до-однієї, розрізнення за портами.

**Напрямок.** Інтерфейс до внутрішньої мережі позначають `ip nat inside`, до зовнішньої `ip nat outside`. Правила описують, **що** транслюється (ACL чи пряма вказівка) і **у що** (адреса, пул чи інтерфейс).

## Хід роботи

### Крок 1. Побудуйте топологію й налаштуйте адреси

На R1 `ip route 0.0.0.0 0.0.0.0 198.51.100.1`; на ISP маршрут до публічного блоку: `ip route 203.0.113.0 255.255.255.0 198.51.100.2`. Позначте інтерфейси.

```
interface gi0/0
 ip nat inside
interface gi0/1
 ip nat inside
interface gi0/2
 ip nat outside
```

### Крок 2. Налаштуйте статичний NAT для вебсервера

Сервер доступний ззовні за адресою 203.0.113.20 (порт 80).

```
ip nat inside source static 192.168.20.10 203.0.113.20
```

### Крок 3. Налаштуйте динамічний NAT із пулом

Клієнти LAN отримують публічні адреси з пулу 203.0.113.100-110. Якщо адреси в пулі закінчуються, використовується PAT на інтерфейсі.

```
access-list 10 permit 192.168.10.0 0.0.0.255
ip nat pool PUBLIC 203.0.113.100 203.0.113.110 netmask 255.255.255.0
ip nat inside source list 10 pool PUBLIC
! запасний варіант: PAT на адресу інтерфейсу
ip nat inside source list 10 interface gi0/2 overload
```

### Крок 4. Перевірте трансляції

З PC1 пропінгуйте EXT, з EXT відкрийте `http://203.0.113.20`. Перегляньте таблицю.

![[attachments/ksm-pt26-step4.svg|820]]
*Крок 4. Статичний запис для сервера та динамічні для клієнта. Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 5. Проаналізуйте відмінності

Складіть таблицю: для кожного виду NAT опишіть, що в стовпчиках Inside local та Inside global, і як вони змінюються з кожним новим з'єднанням.

> [!tip] Для статичного запису порти не відображаються, поки немає з'єднань; для PAT завжди видно порти.

## Завдання для самостійного виконання

Поверніть `no ip nat inside source list 10 pool PUBLIC` і залишіть лише PAT. З двох комп'ютерів одночасно відкрийте зовнішній сервер і порівняйте записи таблиці: дві різні внутрішні адреси мають одну зовнішню з різними портами. Поясніть, чому PAT не вимагає пулу.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базової топології |
|---|---|
| 1 | статичний NAT 192.168.20.10 → 203.0.113.20, пул 203.0.113.100-110 |
| 2 | статичний NAT лише для порту 80 (`ip nat inside source static tcp 192.168.20.10 80 203.0.113.20 80`) |
| 3 | пул з двох адрес; перевірити відмову третього клієнта |
| 4 | лише PAT на інтерфейсі Gi0/2 |
| 5 | два сервери: web (203.0.113.20) та ftp (203.0.113.21) |

## Типові помилки

- Не виконати `copy running-config startup-config`: після перезавантаження налаштування зникнуть.
- Не підписати пристрої й порти: у звіті неможливо зіставити скриншот зі схемою.
- Переплутати inside та outside.
- Не маршрутизувати публічний блок до R1 на стороні ISP: відповіді не повертаються.
- Пул адрес не відповідає масці.
