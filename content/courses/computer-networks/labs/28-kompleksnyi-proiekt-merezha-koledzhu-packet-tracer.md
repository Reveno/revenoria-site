# Комплексний проєкт: мережа коледжу в Packet Tracer

> [!abstract] Пов'язана лекція
> [[courses/computer-networks/lectures/45-proiektuvannia-merezhi-pidpryiemstva|Лекція 45. Проєктування мережі підприємства]], [[courses/computer-networks/lectures/14-dhcp-nat-pat-ta-spysky-dostupu-acl|Лекція 14. DHCP, NAT-PAT та списки доступу ACL]], [[courses/computer-networks/lectures/16-dynamichna-marshrutyzatsiia-ospf|Лекція 16. Динамічна маршрутизація OSPF]]. Підсумкова робота: ви збираєте в одну мережу VLAN, DHCP, динамічну маршрутизацію, списки доступу й NAT.

## Навіщо ця робота

Усі окремі технології, які ви вивчали (VLAN, маршрутизація, DHCP, ACL, NAT), у реальній мережі працюють **разом**, і їхня взаємодія створює нові проблеми: DHCP-запит не проходить через ACL, NAT не транслює мережу, яку не оголошено в OSPF. Єдиний спосіб навчитися бачити такі взаємозв'язки це зібрати все в одному проєкті й налагодити його від початку до кінця.

Вам пропонується спроєктувати й налаштувати мережу коледжу з головним корпусом, філією й виходом в інтернет. Завдання поділено на етапи з контрольними перевірками, але всі налаштування ви обираєте самі. Це підсумкова практична робота, за якою оцінюється вміння працювати з мережею як із системою.

## Мета

Навчитися проєктувати й налаштовувати комплексну мережу: план адресації з VLAN, router-on-a-stick, DHCP із виключеннями, OSPF між маршрутизаторами, списки доступу між зонами та NAT із перевантаженням для виходу в інтернет, а також проводити наскрізне тестування й документувати результат.

Після заняття ви повинні вміти:

- складати адресний план і розподіляти VLAN;
- комбінувати VLAN, DHCP, OSPF, ACL та NAT в одній мережі;
- поширювати маршрут за замовчуванням через OSPF;
- тестувати мережу за сценаріями та діагностувати збої;
- документувати налаштування й результати;

## Обладнання та програмне забезпечення

- Комп'ютер із Cisco Packet Tracer 8.x (безкоштовне завантаження з netacad.com після реєстрації в Cisco Networking Academy).
- Файл-заготовка не потрібен: топологію ви будуєте самостійно за схемою нижче.
- Ключові пристрої моделі: три маршрутизатори (R1 головний, R2 філія, ISP), два комутатори 2960, шість комп'ютерів, два сервери.

## Теоретична частина

**Порядок налагодження комплексної мережі:** (1) фізичний рівень та VLAN, (2) адресація та шлюзи, (3) DHCP, (4) внутрішня маршрутизація (OSPF) і маршрут за замовчуванням, (5) NAT, (6) списки доступу в останню чергу, бо вони найчастіше «ламають» те, що вже працювало. На кожному етапі виконується контрольний тест, інакше помилки накопичуються.

**Політика проєкту.** Викладачі мають доступ до серверів і інтернету; студенти лише до вебсервера (80/443) і DNS (53) серверної VLAN та інтернету, але не до викладачів; філія має доступ до серверів і інтернету; керування з VLAN 99.

## Хід роботи

### Крок 1. VLAN, транки й підінтерфейси

Створіть VLAN 10, 20, 30, 99 на SW1, призначте порти, транк до R1; підінтерфейси на R1 (`encapsulation dot1Q N`, для VLAN 99 `native`).

```
! R1
interface gi0/0
 no shutdown
interface gi0/0.10
 encapsulation dot1Q 10
 ip address 10.20.10.1 255.255.255.0
interface gi0/0.20
 encapsulation dot1Q 20
 ip address 10.20.20.1 255.255.255.0
interface gi0/0.30
 encapsulation dot1Q 30
 ip address 10.20.30.1 255.255.255.0
interface gi0/0.99
 encapsulation dot1Q 99 native
 ip address 10.20.99.1 255.255.255.0
```

### Крок 2. DHCP на R1 та R2

Виключіть службові адреси й створіть пули для VLAN 10, 20 (і для філії на R2).

```
! R1
ip dhcp excluded-address 10.20.10.1 10.20.10.19
ip dhcp excluded-address 10.20.20.1 10.20.20.19
ip dhcp pool VLAN10
 network 10.20.10.0 255.255.255.0
 default-router 10.20.10.1
 dns-server 10.20.30.11
ip dhcp pool VLAN20
 network 10.20.20.0 255.255.255.0
 default-router 10.20.20.1
 dns-server 10.20.30.11
! R2
ip dhcp excluded-address 10.20.50.1 10.20.50.19
ip dhcp pool BRANCH
 network 10.20.50.0 255.255.255.0
 default-router 10.20.50.1
 dns-server 10.20.30.11
```

### Крок 3. OSPF і маршрут за замовчуванням

OSPF між R1 та R2, на R1 поширте маршрут за замовчуванням (`default-information originate`) для філії.

```
! R1
ip route 0.0.0.0 0.0.0.0 198.51.100.1
router ospf 1
 router-id 1.1.1.1
 network 10.20.10.0 0.0.0.255 area 0
 network 10.20.20.0 0.0.0.255 area 0
 network 10.20.30.0 0.0.0.255 area 0
 network 10.20.100.0 0.0.0.3 area 0
 default-information originate
 passive-interface gi0/0.10
 passive-interface gi0/0.20
 passive-interface gi0/0.30
! R2
router ospf 1
 router-id 2.2.2.2
 network 10.20.50.0 0.0.0.255 area 0
 network 10.20.100.0 0.0.0.3 area 0
 passive-interface gi0/0
```

### Крок 4. NAT для виходу в інтернет

PAT для всієї внутрішньої адресації 10.20.0.0/16.

```
access-list 1 permit 10.20.0.0 0.0.255.255
ip nat inside source list 1 interface gi0/2 overload
interface gi0/0.10
 ip nat inside
interface gi0/0.20
 ip nat inside
interface gi0/0.30
 ip nat inside
interface gi0/1
 ip nat inside
interface gi0/2
 ip nat outside
```

### Крок 5. Списки доступу для студентів

Студенти (VLAN 20) мають доступ до вебсервера й DNS у VLAN 30 та інтернету, але не до викладачів і керування.

```
ip access-list extended STUDENTS-IN
 permit udp 10.20.20.0 0.0.0.255 host 10.20.30.11 eq 53
 permit tcp 10.20.20.0 0.0.0.255 host 10.20.30.10 eq 80
 permit tcp 10.20.20.0 0.0.0.255 host 10.20.30.10 eq 443
 permit udp any eq 68 any eq 67
 deny   ip 10.20.20.0 0.0.0.255 10.20.0.0 0.0.255.255
 permit ip 10.20.20.0 0.0.0.255 any
interface gi0/0.20
 ip access-group STUDENTS-IN in
```

### Крок 6. Наскрізне тестування

Виконайте перевірки з таблиці й зафіксуйте результат: що має працювати й що має бути заборонено.

![[attachments/ksm-pt28-step6.svg|820]]
*Крок 7. NAT та лічильники ACL після тестування. Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

> [!tip] Таблиця тестів: викладач → сервер (так), студент → вебсервер (так), студент → викладач (ні), філія → сервери (так), будь-хто → інтернет (так, через NAT).

## Завдання для самостійного виконання

Додайте політику для філії: PC філії має доступ до серверів VLAN 30 лише по TCP 80/443 і DNS, а до VLAN 10 не має доступу. Поясніть, на якому інтерфейсі й у якому напрямку ви застосували цей список і чому.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базової топології |
|---|---|
| 1 | базова схема з методички |
| 2 | замість філії другий корпус із VLAN 40 і 50 |
| 3 | OSPF ззовні замінити статичними маршрутами |
| 4 | додати HSRP для шлюзу VLAN 10 (потрібен другий маршрутизатор) |
| 5 | додати Port Security на порти доступу й SSH замість Telnet |

## Типові помилки

- Не виконати `copy running-config startup-config`: після перезавантаження налаштування зникнуть.
- Не підписати пристрої й порти: у звіті неможливо зіставити скриншот зі схемою.
- Застосувати ACL студентів, не дозволивши DHCP (UDP 67/68): клієнти не отримують адреси.
- Не оголосити мережу в OSPF: вона недосяжна для філії.
- Не позначити всі внутрішні підінтерфейси як `ip nat inside`.

## Контрольні питання

1. У якому порядку слід налагоджувати комплексну мережу й чому?
2. Чому DHCP-трафік треба враховувати в ACL?
3. Як філія дізнається про маршрут за замовчуванням?
4. Які ризики несе об'єднання всіх служб на одному маршрутизаторі?

## Вимоги до звіту

Звіт подається без титульного листа й містить: тему й мету; схему топології зі своїми підписами; таблицю адресації; повний перелік введених команд; скриншоти ключових кроків із Packet Tracer (кожен із видимим ім'ям пристрою та часом); відповіді на контрольні питання; висновки. Файл проєкту `.pkt` додається окремо.

## Критерії оцінювання

| Оцінка | Що враховується |
|---|---|
| 5 | усі кроки виконано, перевірки пройдено, самостійне завдання виконано й пояснено, звіт повний |
| 4 | кроки виконано, є незначні неточності у звіті чи поясненнях |
| 3 | виконано основну частину, самостійне завдання не виконано або не пояснено |
| 2 | топологія не працює, звіт неповний |
