# Захист портів комутатора функцією Port Security

> [!abstract] Пов'язана лекція
> [[courses/computer-networks/lectures/06-komutatsiia-vlan-ta-tranky|Лекція 6. Комутація, VLAN та транки]], [[courses/computer-networks/lectures/42-merezheva-bezpeka|Лекція 42. Мережева безпека]]. Ви обмежуєте, які пристрої можуть користуватися портом комутатора, і спостерігаєте реакцію на порушення.

## Навіщо ця робота

Комутатор приймає будь-який пристрій, підключений до вільного порту: достатньо вставити кабель, і зловмисник у мережі. Функція Port Security дозволяє прив'язати порт до конкретних MAC-адрес і задати реакцію на порушення: проігнорувати, повідомити чи вимкнути порт. Це проста, але дієва міра проти підключення сторонніх пристроїв і проти атак на переповнення таблиці MAC-адрес.

У лабораторній ви налаштуєте захист, підключите «чужий» пристрій і побачите, як порт переходить у стан err-disabled, а потім відновите його. Ця навичка потрібна кожному, хто адмініструє комутатори доступу.

## Мета

Навчитися налаштовувати Port Security на портах доступу: ліміт MAC-адрес, «липкі» адреси, режими реакції на порушення, діагностика й відновлення порту після порушення.

Після заняття ви повинні вміти:

- вмикати Port Security й задавати максимальну кількість MAC-адрес;
- використовувати «липке» запам'ятовування адрес (sticky);
- розрізняти режими protect, restrict, shutdown;
- переглядати стан порту й лічильник порушень;
- відновлювати порт зі стану err-disabled;

## Обладнання та програмне забезпечення

- Комп'ютер із Cisco Packet Tracer 8.x (безкоштовне завантаження з netacad.com після реєстрації в Cisco Networking Academy).
- Файл-заготовка не потрібен: топологію ви будуєте самостійно за схемою нижче.
- Ключові пристрої моделі: комутатор 2960-24TT, два комп'ютери, концентратор (Hub-PT) та сервер.

## Теоретична частина

**Режими реакції.** `protect` мовчки відкидає кадри з незнайомих адрес; `restrict` відкидає й збільшує лічильник порушень, пише повідомлення в журнал; `shutdown` (за замовчуванням) переводить порт у стан **err-disabled**, тобто вимикає його: щоб увімкнути, адміністратор виконує `shutdown` і `no shutdown`.

**Sticky.** Із командою `switchport port-security mac-address sticky` комутатор запам'ятовує вивчені адреси в конфігурації, і не потрібно вводити їх вручну.

## Хід роботи

### Крок 1. Побудуйте топологію й перевірте зв'язок

Додайте комутатор, концентратор, два комп'ютери й сервер. Налаштуйте адреси. Перевірте, що PC1 пінгує сервер.

### Крок 2. Увімкніть Port Security на порту Fa0/1

Порт має бути в режимі доступу: Port Security не працює на динамічних портах. Дозвольте одну адресу, увімкніть sticky та режим shutdown.

```
configure terminal
interface fa0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 1
 switchport port-security mac-address sticky
 switchport port-security violation shutdown
end
```

### Крок 3. Вивчіть адресу легітимного пристрою

Надішліть ping із PC1, щоб комутатор запам'ятав його адресу, і перегляньте стан порту.

![[attachments/ksm-pt20-step3.svg|820]]
*Крок 3. Порт захищено, вивчена одна адреса. Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 4. Змоделюйте порушення

Надішліть ping із пристрою ROGUE через той самий концентратор. Комутатор бачить другу MAC-адресу на порту з лімітом 1 і застосовує реакцію shutdown.

![[attachments/ksm-pt20-step4.svg|820]]
*Крок 4. Порт у стані err-disabled після порушення. Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

> [!tip] У Packet Tracer лінк на комутаторі стає червоним: це ознака вимкненого порту.

### Крок 5. Відновіть порт

Видаліть чужий пристрій, потім перезапустіть порт: спершу `shutdown`, потім `no shutdown`. Перевірте, що PC1 знову пінгує сервер.

```
configure terminal
interface fa0/1
 shutdown
 no shutdown
end
show port-security interface fa0/1
```

## Завдання для самостійного виконання

Змініть режим на `restrict`, повторіть порушення й порівняйте поведінку: порт лишається активним, а лічильник порушень росте. Поясніть, у якому випадку краще shutdown, а в якому restrict (наприклад, для кімнати переговорів із частою зміною пристроїв).

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базової топології |
|---|---|
| 1 | Порт Fa0/1, maximum 1, режим shutdown |
| 2 | Порт Fa0/5, maximum 2, режим restrict |
| 3 | Порт Fa0/10, maximum 1, режим protect, aging 10 хв |
| 4 | Порти Fa0/1-4 одночасно (`interface range`), maximum 1 |
| 5 | Порт Fa0/2, статична адреса задається вручну замість sticky |

## Типові помилки

- Не виконати `copy running-config startup-config`: після перезавантаження налаштування зникнуть.
- Не підписати пристрої й порти: у звіті неможливо зіставити скриншот зі схемою.
- Вмикати Port Security на порту без `switchport mode access`.
- Забути, що `shutdown`-режим вимикає порт: адміністратор мусить його вручну відновити.

## Контрольні питання

1. Які режими реакції на порушення існують і чим вони відрізняються?
2. Що таке sticky-адреси?
3. Чому Port Security вимагає режиму access?
4. Як відновити порт зі стану err-disabled?

## Вимоги до звіту

Звіт подається без титульного листа й містить: тему й мету; схему топології зі своїми підписами; таблицю адресації; повний перелік введених команд; скриншоти ключових кроків із Packet Tracer (кожен із видимим ім'ям пристрою та часом); відповіді на контрольні питання; висновки. Файл проєкту `.pkt` додається окремо.

## Критерії оцінювання

| Оцінка | Що враховується |
