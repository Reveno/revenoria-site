# Іменовані списки доступу й демілітаризована зона

> [!abstract] Пов'язана лекція
> [[courses/computer-networks/lectures/14-dhcp-nat-pat-ta-spysky-dostupu-acl|Лекція 14. DHCP, NAT-PAT та списки доступу ACL]], [[courses/computer-networks/lectures/42-merezheva-bezpeka|Лекція 42. Мережева безпека]]. Ви налаштовуєте зону DMZ для вебсервера й іменовані ACL, що обмежують обмін між внутрішньою мережею, DMZ та зовнішньою мережею.

## Навіщо ця робота

Вебсервер, доступний з інтернету, це найвразливіша точка організації: його будуть сканувати й атакувати постійно. Якщо його поставити у внутрішню мережу, зламаний сервер стане плацдармом для атаки на комп'ютери співробітників. Тому такі сервери виносять у окрему **демілітаризовану зону** (DMZ): сегмент, у який ззовні можна потрапити лише на потрібні порти, а з нього всередину не можна взагалі.

Правила, що це забезпечують, пишуться списками доступу. У цій роботі ви створите три іменовані списки для трьох напрямків і перевірите, що вони дають саме потрібну політику: співробітники ходять до DMZ і в інтернет, зовнішні користувачі бачать лише веб-порти, а DMZ не має доступу до внутрішньої мережі.

## Мета

Навчитися проєктувати політику доступу для трьох зон (LAN, DMZ, зовнішня мережа), складати іменовані розширені ACL, застосовувати їх на інтерфейсах, перевіряти дію правил за лічильниками й порядком.

Після заняття ви повинні вміти:

- складати іменовані розширені ACL;
- використовувати `established` для відповідей на TCP-з'єднання;
- обирати інтерфейс і напрям застосування;
- перевіряти правила за лічильниками збігів;
- пояснювати принцип зони DMZ;

## Обладнання та програмне забезпечення

- Комп'ютер із Cisco Packet Tracer 8.x (безкоштовне завантаження з netacad.com після реєстрації в Cisco Networking Academy).
- Файл-заготовка не потрібен: топологію ви будуєте самостійно за схемою нижче.
- Ключові пристрої моделі: маршрутизатор 2911 (три інтерфейси), маршрутизатор ISP, два комутатори, комп'ютери, сервер.

## Теоретична частина

**Іменовані ACL** зручніші за нумеровані: правила мають номери рядків, їх можна вставляти й видаляти окремо (`no 20`). **Принцип**: ближче до джерела й на вході (`in`). Для відповідей на з'єднання, ініційовані з іншого боку, використовують `established` (TCP-пакети з прапорцем ACK чи RST), бо ACL у Packet Tracer і на звичайних маршрутизаторах працює **без стану**.

**Політика трьох зон.** LAN → DMZ: лише 80 та 443; LAN → інтернет: усе; DMZ → LAN: нічого (крім відповідей); зовнішня мережа → DMZ: лише 80 та 443; зовнішня → LAN: нічого.

## Хід роботи

### Крок 1. Побудуйте топологію й перевірте зв'язок без ACL

Налаштуйте адреси, на R1 додайте маршрут за замовчуванням `ip route 0.0.0.0 0.0.0.0 203.0.113.1`, на ISP маршрут `ip route 192.168.0.0 255.255.0.0 203.0.113.2`. Переконайтеся, що PC1 пінгує сервер WEB та EXT.

> [!tip] Маршрут на ISP до приватних мереж нереалістичний (так не буває в інтернеті); ми застосовуємо його лише щоб обійтися без NAT, який налаштуємо в наступній лабораторній.

### Крок 2. Складіть ACL для трафіку з LAN

Співробітники мають доступ до вебсервера в DMZ (80, 443) і будь-якого вузла інтернету; інший доступ до DMZ заборонено.

```
ip access-list extended LAN-IN
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.10 eq 80
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.10 eq 443
 deny   ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip 192.168.10.0 0.0.0.255 any
```

### Крок 3. Складіть ACL для трафіку з DMZ

Сервер у DMZ може лише відповідати на з'єднання (`established`) і спілкуватися із зовнішньою мережею (оновлення). Усе, що адресовано LAN, заборонено.

```
ip access-list extended DMZ-IN
 permit tcp 192.168.20.0 0.0.0.255 192.168.10.0 0.0.0.255 established
 deny   ip 192.168.20.0 0.0.0.255 192.168.10.0 0.0.0.255
 permit ip 192.168.20.0 0.0.0.255 any
```

### Крок 4. Складіть ACL для зовнішнього трафіку й застосуйте всі списки

Зовнішні клієнти бачать лише веб-порти сервера DMZ; відповіді на з'єднання з LAN дозволені.

```
ip access-list extended OUT-IN
 permit tcp any host 192.168.20.10 eq 80
 permit tcp any host 192.168.20.10 eq 443
 permit tcp any 192.168.10.0 0.0.0.255 established
 permit icmp any any echo-reply
 deny   ip any any log
interface gi0/0
 ip access-group LAN-IN in
interface gi0/1
 ip access-group DMZ-IN in
interface gi0/2
 ip access-group OUT-IN in
```

### Крок 5. Перевірте політику й лічильники

З PC1 відкрийте `http://192.168.20.10` (успіх), з EXT відкрийте цю ж адресу (успіх), з EXT спробуйте ping на PC1 (відмова). Виведіть лічильники правил.

## Завдання для самостійного виконання

Скомпрометований сервер у DMZ намагається підключитися до PC1 по SSH. Покажіть, що ACL DMZ-IN відкидає ці спроби (лічильник рядка 20 росте). Додайте до OUT-IN правило, що дозволяє адміністратору з адреси 198.51.100.50 доступ по SSH (22) лише до маршрутизатора, і поясніть, чому його слід поставити перед `deny`.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базової топології |
|---|---|
| 1 | DMZ 192.168.20.0/24, веб 80/443 |
| 2 | DMZ 172.16.50.0/24, сервер FTP (21) замість вебу |
| 3 | додати сервер пошти SMTP (25) у DMZ |
| 4 | LAN також може `ping` сервер DMZ |
| 5 | дозволити зовнішнім користувачам лише 443 (HTTPS), порт 80 заборонити |

## Типові помилки

- Не виконати `copy running-config startup-config`: після перезавантаження налаштування зникнуть.
- Не підписати пристрої й порти: у звіті неможливо зіставити скриншот зі схемою.
- Поставити `permit ip any any` перед `deny`: решта правил не спрацьовує.
- Забути `established`: відповіді на з'єднання блокуються.
- Застосувати список не в тому напрямку (`out` замість `in`).

Звіт подається без титульного листа й містить: тему й мету; схему топології зі своїми підписами; таблицю адресації; повний перелік введених команд; скриншоти ключових кроків із Packet Tracer (кожен із видимим ім'ям пристрою та часом); відповіді на контрольні питання; висновки. Файл проєкту `.pkt` додається окремо.

## Критерії оцінювання

| Оцінка | Що враховується |
|---|---|
| 5 | усі кроки виконано, перевірки пройдено, самостійне завдання виконано й пояснено, звіт повний |
| 4 | кроки виконано, є незначні неточності у звіті чи поясненнях |
| 3 | виконано основну частину, самостійне завдання не виконано або не пояснено |
