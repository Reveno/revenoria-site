# Початкове налаштування комутатора та захищений доступ SSH

> [!abstract] Пов'язана лекція
> [[courses/computer-networks/lectures/03-merezheve-obladnannia|Лекція 3. Мережеве обладнання]], [[courses/computer-networks/lectures/13-bazove-nalashtuvannia-marshrutyzatora-cisco|Лекція 13. Базове налаштування маршрутизатора Cisco IOS]]. Ви налаштовуєте керований комутатор Cisco з нуля: ім'я, паролі, керувальну VLAN, SSH замість Telnet.

## Навіщо ця робота

Комутатор у мережі працює «мовчки», але керувати ним потрібно: змінювати конфігурацію, дивитися таблиці, шукати несправності. Якщо доступ до керування лишити відкритим, будь-хто у вашій мережі зможе змінити налаштування. Тому перша дія на новому комутаторі це не підключення станцій, а налаштування безпечного керування: окрема керувальна VLAN, паролі, шифрований віддалений доступ SSH.

У цій лабораторній вам доведеться виконати саме цю процедуру в Packet Tracer і переконатися, що Telnet відхиляється, а SSH працює. Вона відтворюється на реальному обладнанні майже без змін.

## Мета

Навчитися виконувати початкове налаштування комутатора Cisco Catalyst 2960: ім'я, паролі, банер, керувальна VLAN з адресою, захищений віддалений доступ SSH, перевірка підключення з робочої станції.

Після заняття ви повинні вміти:

- налаштовувати ім'я, паролі, банер на комутаторі;
- створювати керувальну VLAN та призначати адресу керування й шлюз;
- налаштовувати SSH версії 2 із локальним користувачем;
- забороняти Telnet на лініях VTY;
- перевіряти підключення з робочої станції;

## Обладнання та програмне забезпечення

- Комп'ютер із Cisco Packet Tracer 8.x (безкоштовне завантаження з netacad.com після реєстрації в Cisco Networking Academy).
- Файл-заготовка не потрібен: топологію ви будуєте самостійно за схемою нижче.
- Ключові пристрої моделі: комутатор Catalyst 2960-24TT, два комп'ютери, прямі кабелі «Copper Straight-Through».

## Теоретична частина

**Керувальна VLAN.** Адресу керування комутатор отримує не на фізичному порту, а на віртуальному інтерфейсі VLAN (SVI). Для безпеки під керування виділяють окрему VLAN (тут 99): тоді до комутатора можна достукатися лише з цієї мережі, а не з мереж користувачів.

**SSH.** Для SSH потрібні: ім'я пристрою та домену (з них будується назва ключа), пара RSA-ключів, локальний користувач і налаштовані лінії VTY (`transport input ssh`, `login local`). Telnet передає пароль відкритим текстом, тому його забороняють.

## Хід роботи

### Крок 1. Побудуйте топологію

У Packet Tracer додайте комутатор 2960-24TT і два комп'ютери. З'єднайте їх кабелем «Copper Straight-Through» за схемою. Задайте комп'ютерам адреси з таблиці (Desktop → IP Configuration).

> [!tip] Зелені трикутники на лінках з'являються не одразу: комутатору потрібні кілька секунд (STP).

### Крок 2. Виконайте базове налаштування

Відкрийте вкладку CLI комутатора й введіть команди. Банер попереджає про відповідальність за несанкціонований доступ, `enable secret` зберігає пароль хешованим, `service password-encryption` ховає решту паролів.

```
enable
configure terminal
hostname SW1
no ip domain-lookup
banner motd #Тільки для авторизованого персоналу#
enable secret <Складний_пароль>
service password-encryption
vlan 99
 name MGMT
exit
interface vlan 99
 ip address 192.168.99.2 255.255.255.0
 no shutdown
exit
ip default-gateway 192.168.99.1
interface range fa0/1 - 2
 switchport mode access
 switchport access vlan 99
 no shutdown
```

### Крок 3. Налаштуйте SSH

Згенеруйте ключі RSA (мінімальний розмір для SSH версії 2 це 768 біт, рекомендовано 2048), створіть локального користувача й дозвольте на лініях VTY лише SSH.

```
ip domain-name lab.local
crypto key generate rsa modulus 2048
ip ssh version 2
username admin secret <Пароль_адміна>
line vty 0 15
 transport input ssh
 login local
 exec-timeout 5 0
end
```

![[attachments/ksm-pt19-step3.svg|820]]
*Крок 3. Перевірка налаштувань SSH на комутаторі. Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

> [!tip] Якщо після `crypto key generate rsa` команда `ip ssh version 2` не приймається, переконайтеся, що задано ім'я та домен.

### Крок 4. Перевірте підключення з робочої станції

На PC1 відкрийте Desktop → Command Prompt і виконайте `ssh -l admin 192.168.99.2`. Потім спробуйте `telnet 192.168.99.2`: підключення має бути відхилено.

![[attachments/ksm-pt19-step4.svg|820]]
*Крок 4. SSH працює, Telnet не приймається. Вигляд консолі Packet Tracer (приклад очікуваного виводу; ваші значення можуть трохи відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 5. Збережіть конфігурацію

Виконайте `copy running-config startup-config`, потім перезавантажте комутатор (`reload`) і переконайтеся, що налаштування збереглися (`show running-config`).

```
copy running-config startup-config
```

## Завдання для самостійного виконання

Додайте до топології третій комп'ютер у VLAN 10 (порт Fa0/3, адреса 192.168.10.10/24) і поясніть, чому він не зможе підключитися до комутатора по SSH. Запропонуйте, що потрібно змінити (маршрутизація між VLAN чи дозвіл SSH із VLAN 10), і оцініть ризик другого варіанта.

## Типові помилки

- Не виконати `copy running-config startup-config`: після перезавантаження налаштування зникнуть.
- Не підписати пристрої й порти: у звіті неможливо зіставити скриншот зі схемою.
- Залишити `transport input all`: Telnet залишається доступним.
- Не задати шлюз керування: підключитися можна лише з тієї ж підмережі.

## Вимоги до звіту

Звіт подається без титульного листа й містить: тему й мету; схему топології зі своїми підписами; таблицю адресації; повний перелік введених команд; скриншоти ключових кроків із Packet Tracer (кожен із видимим ім'ям пристрою та часом); відповіді на контрольні питання; висновки. Файл проєкту `.pkt` додається окремо.

## Критерії оцінювання

| Оцінка | Що враховується |
|---|---|
| 5 | усі кроки виконано, перевірки пройдено, самостійне завдання виконано й пояснено, звіт повний |
| 4 | кроки виконано, є незначні неточності у звіті чи поясненнях |
