# Модель кеш-пам'яті на Python

> [!abstract] Пов'язана лекція
> [[courses/computer-architecture/lectures/18-iierarkhiia-pamiati-ta-osnovni-typy-ram-rom|Лекція 18. Ієрархія пам'яті та основні типи (RAM, ROM, Flash)]], [[courses/computer-architecture/lectures/19-kesh-pamiat-ta-virtualna-pamiat|Лекція 19. Кеш-пам'ять та віртуальна пам'ять]]. Лабораторна робота дозволяє «побачити» кеш: ви пишете невелику програму-модель кеша, подаєте їй різні послідовності звернень до пам'яті й вимірюєте частку влучань. Зокрема, перевіряється, чому обхід матриці по рядках швидший за обхід по стовпцях.

## Мета

Навчитися моделювати кеш прямого й наборно-асоціативного відображення, оцінювати частку влучань для різних шаблонів звернень і пояснювати результати локальністю доступу.

Після заняття ви повинні вміти:

- розбивати адресу на тег, набір і зсув у програмі;
- моделювати політику витіснення LRU;
- порівнювати прямий і наборно-асоціативний кеші;
- пов'язувати результати із просторовою локальністю.

## Теоретична частина

Теорія в [[courses/computer-architecture/lectures/18-iierarkhiia-pamiati-ta-osnovni-typy-ram-rom|лекції 18]] та [[courses/computer-architecture/lectures/19-kesh-pamiat-ta-virtualna-pamiat|лекції 19]]. Адреса пам'яті ділиться на номер блока (адреса, поділена націло на розмір рядка), індекс набору (номер блока за модулем кількості наборів) і тег (решта). Кеш, що налічує `n_lines` рядків та `ways` каналів, містить `n_lines // ways` наборів.

## Хід роботи

### Частина 1. Модель

1. Створіть файл `cache.py`:

```python
def simulate(addresses, n_lines=32, ways=1, line_size=64):
    sets = n_lines // ways
    cache = [[] for _ in range(sets)]   # у кожному наборі список тегів, останній найновіший
    hits = 0
    for a in addresses:
        block = a // line_size
        s = block % sets
        tag = block // sets
        if tag in cache[s]:
            hits += 1
            cache[s].remove(tag)
            cache[s].append(tag)
        else:
            if len(cache[s]) >= ways:
                cache[s].pop(0)          # LRU: найстаріший
            cache[s].append(tag)
    return hits, len(addresses)

if __name__ == "__main__":
    h, n = simulate([0, 4, 0, 8, 4, 0], n_lines=4, ways=1, line_size=1)
    print("direct:", h, "of", n)
    h, n = simulate([0, 4, 0, 8, 4, 0], n_lines=4, ways=2, line_size=1)
    print("2-way:", h, "of", n)
```

2. Запустіть. Очікуваний результат: прямий кеш 0 влучань із 6, двоканальний 1 влучання з 6 (збігається з практичною роботою про ієрархію пам'яті).

### Частина 2. Експерименти

3. Додайте функції, що генерують послідовності адрес для матриці 64×64 цілих по 4 байти:

```python
def row_major(n=64):
    return [(i * n + j) * 4 for i in range(n) for j in range(n)]

def col_major(n=64):
    return [(i * n + j) * 4 for j in range(n) for i in range(n)]
```

4. Для кеша на 32 рядки по 64 байти (прямий, потім 2-, 4-, 8-канальний) запишіть частку влучань для обох обходів у таблицю. Очікування: обхід по рядках близько 94 % влучань, оскільки в одному рядку кеша міститься 16 чисел; обхід по стовпцях значно гірший (близько нуля для малого кеша).
5. Збільшуйте кеш (64, 128, 256 рядків). Знайдіть розмір, за якого обхід по стовпцях починає давати влучання, і поясніть, чому.
6. Додайте випадкові звернення (`random.randrange(0, 1<<20)`) і запишіть частку влучань. Поясніть різницю.
