# Оцінювання продуктивності багатоядерного процесора

> [!abstract] Пов'язана лекція
> [[courses/computer-architecture/lectures/12-bahatoiaderni-protsesory-ta-paralelni|Лекція 12. Багатоядерні процесори та паралельні обчислення]]. Ви вимірюєте, як програма прискорюється на кількох ядрах, і порівнюєте результат із теорією закону Амдала.

## Навіщо ця робота

Реклама обіцяє «16 ядер»: виходить, у 16 разів швидше? Насправді ні, і ця робота показує, наскільки. Продуктивність багатоядерного процесора залежить від того, яка частина програми справді може виконуватися паралельно, чи не конкурують потоки за пам'ять і кеш, чи не витрачається час на створення потоків і обмін даними. Ви виміряєте реальне прискорення на своєму комп'ютері та порівняєте його з теоретичним.

Результат майже завжди відрізняється від ідеалу, і саме цей розрив є метою вивчення: він пояснює, чому розробники програм так наполегливо шукають спосіб зменшити послідовну частину й чому додавання ядер не «лікує» повільну програму автоматично.

## Мета

Навчитися вимірювати час виконання обчислювальної задачі на різній кількості потоків, розраховувати прискорення S(N) і ефективність E(N), порівнювати виміряні значення із законом Амдала та оцінювати частку послідовного коду.

Після заняття ви повинні вміти:

- визначати кількість фізичних і логічних ядер процесора;
- вимірювати час виконання на N потоках;
- розраховувати прискорення та ефективність;
- порівнювати результат із законом Амдала й визначати граничне прискорення;
- оцінювати частку послідовного коду за результатами вимірювань;

## Обладнання та програмне забезпечення

- Персональний комп'ютер з доступом до мережі Інтернет.
- Довідкові матеріали щодо технічних характеристик компонентів.

Знадобляться комп'ютер, Python 3 (python.org) та текстовий редактор. Кількість ядер можна подивитися в Диспетчері завдань Windows (вкладка «Продуктивність → ЦП», рядки «Ядра» та «Логічні процесори») чи командою `lscpu` у Linux. Під час вимірювань **закрийте інші програми** й підключіть ноутбук до живлення: інакше результати будуть нестабільні через зміну частоти процесора.

## Теоретична частина

Продуктивність багатоядерного процесора залежить не лише від кількості ядер: частина коду принципово послідовна, ядра конкурують за спільну пам'ять і кеш. Тому реальне прискорення завжди менше за кількість ядер, а понад певну межу може навіть спадати.

### Прискорення й ефективність

Якщо $T_1$ час виконання на одному потоці, а $T_N$ на N потоках, то **прискорення** $S(N) = T_1 / T_N$ і **ефективність** $E(N) = S(N) / N$. Ідеальне прискорення $S = N$ (ефективність 100 %) на практиці недосяжне.

### Закон Амдала

Якщо паралельна частка програми p, то $S(N) = 1 / ((1 - p) + p / N)$, і гранично $S_{\max} = 1/(1 - p)$. Зі зворотного боку, виміряне прискорення дозволяє оцінити **частку послідовного коду** за формулою Карпа-Флетта:

$$e = \frac{1/S(N) - 1/N}{1 - 1/N}$$

де e оцінка послідовної частки, включно з накладними витратами на організацію потоків.

### Крок 1. Визначте кількість фізичних і логічних ядер вашого процесора

**Навіщо.** Прискорення зростає майже лінійно до кількості фізичних ядер, а далі значно повільніше, бо два логічні потоки ділять одне ядро. Ця різниця пояснить форму вашого графіка.

**Очікуваний результат.** Рядок на кшталт «6 ядер / 12 логічних процесорів».

**Очікуваний результат.** Час $T_1$ у секундах із похибкою не більше кількох відсотків між запусками.

### Крок 5. Порівняйте отриману криву з теоретичною межею

**Що робити.** Порівняйте виміряне прискорення з теоретичним. Для вашого N розрахуйте граничне $S_{\max}$ за варіантом. Із виміряного $S(N)$ оцініть частку послідовного коду e за формулою Карпа-Флетта.

**Навіщо.** Якщо e набагато більше за очікувану $(1-p)$, значить, у програмі є додаткові накладні витрати (створення потоків, синхронізація, пам'ять). Це типова причина розчарування від багатоядерності.

**Очікуваний результат.** Висновок: «виміряне прискорення S(4) = 2,9 відповідає послідовній частці близько 13 % проти очікуваних 10 %».

## Приклад виконання

**Програма** для вимірювання на Python (використовуємо процеси, а не потоки, бо в Python є глобальне блокування інтерпретатора (GIL), яке не дозволяє потокам виконувати обчислення одночасно):

```python
import time
from multiprocessing import Pool, cpu_count

N_ITEMS = 10_000_000

def chunk_sum(bounds):
    a, b = bounds
    s = 0
    for x in range(a, b):
        s += x * x
    return s

def run(workers):
    step = N_ITEMS // workers
    parts = [(i * step, (i + 1) * step if i < workers - 1 else N_ITEMS) for i in range(workers)]
    t0 = time.perf_counter()
    if workers == 1:
        total = chunk_sum(parts[0])
    else:
        with Pool(workers) as p:
            total = sum(p.map(chunk_sum, parts))
    return time.perf_counter() - t0, total

if __name__ == "__main__":
    print("ядер (логічних):", cpu_count())
    t1, _ = run(1)
    for n in (1, 2, 4, cpu_count()):
        times = sorted(run(n)[0] for _ in range(3))
        tn = times[1]
        s = t1 / tn
        print(f"N={n:2d}  T={tn:6.2f} c  S={s:5.2f}  E={s / n:5.2f}")
```

Блок `if __name__ == "__main__":` обов'язковий у Windows: без нього дочірні процеси запустять програму знову. Для вашого варіанта змініть задачу (сума квадратів, множення матриць тощо) і розмір даних.

**Умовні результати** для 4 ядер: $T_1 = 4{,}0$ с; $T_2 = 2{,}2$ с; $T_4 = 1{,}38$ с. Тоді $S(2) = 1{,}82$ ($E = 91\%$), $S(4) = 2{,}90$ ($E = 72{,}5\%$).

**Теорія Амдала** для p = 0,9: $S(2) = 1/(0{,}1 + 0{,}45) = 1{,}82$, $S(4) = 1/(0{,}1 + 0{,}225) = 3{,}08$, $S_{\max} = 10$. Виміряне S(4) = 2,90 нижче за теоретичне 3,08.

**Частка послідовного коду за Карпом-Флеттом:** $e = (1/2{,}90 - 1/4)/(1 - 1/4) = (0{,}345 - 0{,}25)/0{,}75 \approx 0{,}127$, тобто 12,7 % замість очікуваних 10 %. Різниця пояснюється витратами на створення процесів і передачу даних.

**Для варіанта «p = 50 %, N = 2»:** $S(2) = 1/(0{,}5 + 0{,}25) = 1{,}33$; граничне $S_{\max} = 1/0{,}5 = 2$.

## Типові помилки

- Робити виміри при працюючих інших програмах (браузер, відео): час «скаче».
- Використовувати потоки замість процесів у Python і дивуватися відсутності прискорення (GIL).
- Брати найкращий із запусків замість медіани: це завищує прискорення.
- Порівнювати з Амдалом, не вказавши p і N.
- Використовувати N більше за кількість логічних процесорів: прискорення вже не зростає.

## Контрольні питання

1. Чому прискорення менше за кількість ядер?
2. Чим фізичне ядро відрізняється від логічного?
3. Що таке закон Амдала?
4. Чому надлишок потоків може сповільнити програму?

## Вимоги до звіту

Звіт подається без титульного листа й містить:

1. Тему та мету роботи.
2. Умову завдання (номер варіанта).
3. Хід виконання роботи зі скриншотами ключових кроків.
4. Результати виконання завдань (вихідний код, схеми, конфігурації або протоколи вимірювань, залежно від роботи).
5. Відповіді на контрольні питання.
6. Висновки.

Звіт повинен містити модель процесора, таблицю вимірювань із S(N) та E(N), графік з трьома лініями, розрахунки за Амдалом і Карпом-Флеттом, текст програми й висновок про причини розбіжності з теорією.
