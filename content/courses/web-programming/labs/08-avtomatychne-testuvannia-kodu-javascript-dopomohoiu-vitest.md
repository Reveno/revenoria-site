# Автоматичне тестування коду JavaScript за допомогою Vitest

> [!abstract] Пов'язана лекція
> [[courses/web-programming/lectures/02-javascript-es2024|Лекція 2. JavaScript ES2024+]], [[courses/web-programming/lectures/04-typescript-dlia-vebrozrobky|Лекція 4. TypeScript для веброзробки]]. Ви напишете модульні тести для функцій кошика покупок і навчитеся запускати їх автоматично.

## Навіщо ця робота

Програмісту здається, що код працює, доки він не змінить щось в іншому місці й не зламає ту частину, яку вже перевіряв. Ручна перевірка після кожної правки забирає час, тому її постійно пропускають, і помилки потрапляють до користувачів. Автоматичні тести розв'язують цю проблему: вони запускаються за секунди й одразу показують, що зламалось.

У цій роботі ви створите невеликий модуль логіки інтернет-магазину (кошик), напишете для нього тести з Vitest, побачите, як тест ловить помилку, і навчитеся вимірювати, яку частину коду тести перевіряють.

## Мета

Навчитися писати модульні тести для функцій JavaScript, використовувати твердження, групувати тести, перевіряти виняткові ситуації та вимірювати покриття коду.

Після заняття ви повинні вміти:

- ініціалізувати проєкт і встановлювати Vitest;
- писати тести з `describe`, `it`, `expect`;
- перевіряти винятки та крайові випадки;
- запускати тести й читати звіт;
- вимірювати покриття коду;

## Обладнання та програмне забезпечення

Visual Studio Code, Node.js 20 LTS і новіший (перевірка: `node -v`), npm, сучасний браузер (Chrome або Firefox), Git. Усі приклади працюють локально, без реєстрації в зовнішніх сервісах.

## Теоретична частина

**Модульний тест** перевіряє найменшу частину коду (функцію) окремо від решти. Він має бути швидким, ізольованим і повторюваним. Структура тесту: підготувати вхідні дані, викликати функцію, перевірити результат (схема «arrange, act, assert»). **Крайові випадки**: порожні дані, нуль, від'ємні числа, дуже великі значення; саме тут ховається більшість помилок. **Покриття** показує відсоток рядків, які виконались під час тестів; воно не доводить правильності, але вказує на неперевірені ділянки.

## Хід роботи

### Крок 1. Створіть проєкт

Створіть каталог `shop`, ініціалізуйте проєкт і встановіть Vitest як залежність розробки. У `package.json` додайте `"type": "module"` і скрипт `"test": "vitest run"`.

```bash
mkdir shop && cd shop
npm init -y
npm install -D vitest
```

### Крок 2. Напишіть модуль кошика

Створіть файл `cart.js`. Функція `total` рахує суму, `applyDiscount` застосовує відсоток знижки, `addItem` додає товар або збільшує кількість.

```js
export function addItem(cart, item) {
  const found = cart.find(i => i.id === item.id);
  if (found) return cart.map(i => i.id === item.id ? { ...i, qty: i.qty + item.qty } : i);
  return [...cart, { ...item }];
}

export function total(cart) {
  return cart.reduce((sum, i) => sum + i.price * i.qty, 0);
}

export function applyDiscount(amount, percent) {
  if (percent < 0 || percent > 100) throw new RangeError("percent must be 0..100");
  return Math.round(amount * (100 - percent)) / 100;
}
```

### Крок 3. Напишіть тести

Створіть `cart.test.js`. Групуйте тести блоками `describe`, а кожен сценарій описуйте одним `it`. Назва тесту має читатися як речення: що очікується.

```js
import { describe, it, expect } from "vitest";
import { addItem, total, applyDiscount } from "./cart.js";

describe("addItem", () => {
  it("додає новий товар", () => {
    expect(addItem([], { id: 1, price: 10, qty: 1 })).toEqual([{ id: 1, price: 10, qty: 1 }]);
  });
  it("збільшує кількість наявного товару", () => {
    const cart = [{ id: 1, price: 10, qty: 1 }];
    expect(addItem(cart, { id: 1, price: 10, qty: 2 })[0].qty).toBe(3);
  });
  it("не змінює вихідний кошик", () => {
    const cart = [{ id: 1, price: 10, qty: 1 }];
    addItem(cart, { id: 1, price: 10, qty: 1 });
    expect(cart[0].qty).toBe(1);
  });
});

describe("total", () => {
  it("дорівнює нулю для порожнього кошика", () => expect(total([])).toBe(0));
  it("рахує суму", () => {
    expect(total([{ id: 1, price: 10, qty: 2 }, { id: 2, price: 5, qty: 1 }])).toBe(25);
  });
});

describe("applyDiscount", () => {
  it("застосовує знижку", () => expect(applyDiscount(200, 10)).toBe(180));
  it("кидає помилку для некоректного відсотка", () => {
    expect(() => applyDiscount(100, 150)).toThrow(RangeError);
  });
});
```

### Крок 5. Додайте помилку й подивіться, як її ловить тест

Навмисно зламайте `total`, замінивши `i.price * i.qty` на `i.price`. Запустіть `npm test`: тест «рахує суму» впаде з поясненням, що очікувалось 25, а отримано 15. Верніть правильний код. Це і є користь тестів: помилку знайдено за секунду, а не користувачем.

### Крок 6. Виміряйте покриття

Встановіть пакет покриття `npm i -D @vitest/coverage-v8` і запустіть `npx vitest run --coverage`. У звіті знайдіть відсоток рядків і ті, які не виконувались.

```bash

npx vitest run --coverage
```

## Завдання для самостійного виконання

Додайте функцію `removeItem(cart, id)` та три тести для неї (видалення наявного, видалення відсутнього, незмінність вихідного масиву). Спершу напишіть тести (вони падають), потім реалізацію: так працює підхід TDD.

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

## Типові помилки

- Тест залежить від іншого тесту або від порядку запуску.
- Перевіряти лише «щасливий шлях» без крайових випадків.
- Змінювати вихідні дані в тесті й ламати інші.
- Писати тест, що завжди проходить (порожнє твердження).
- Гнатися за 100 % покриття замість осмислених перевірок.

3. Що показує покриття коду і чого воно не гарантує?
4. У чому ідея підходу TDD?

## Вимоги до звіту

Звіт подається без титульного листа й містить: тему й мету; повний перелік виконаних команд або код; скриншоти ключових кроків (із видимим запрошенням терміналу або вікном редактора); відповіді на контрольні питання; висновки.

## Критерії оцінювання

| Оцінка | Що враховується |
|---|---|
| 5 | усі кроки виконано, результати пояснено, самостійне завдання виконано, звіт повний |
| 4 | кроки виконано, є незначні неточності в поясненнях |
| 3 | виконано основну частину, самостійне завдання не виконано |
| 2 | результат не отримано, звіт неповний |
