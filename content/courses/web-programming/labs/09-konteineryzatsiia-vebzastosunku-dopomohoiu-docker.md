# Контейнеризація вебзастосунку за допомогою Docker

> [!abstract] Пов'язана лекція
> [[courses/web-programming/lectures/08-node-js-ta-express-js-osnovy|Лекція 8. Node.js та Express.js - основи]], [[courses/web-programming/lectures/14-git-ci-cd-deploi-ta-ekonomika-vebrozrobky|Лекція 14. Git, CI-CD, деплой та економіка веброзробки]]. Ви упакуєте простий Node.js-застосунок у контейнер і запустите його за допомогою Docker Compose.

## Навіщо ця робота

«У мене на комп'ютері працює» це одна з найвідоміших фраз програмістів. Причина зазвичай у відмінностях середовища: інша версія Node.js, відсутня бібліотека, інші змінні оточення. Контейнер вирішує проблему, упаковуючи застосунок разом з усім, що йому потрібно, в один образ, який однаково запускається на ноутбуці, сервері розробника та в хмарі.

Ви створите крихітний вебсервер, напишете Dockerfile, зберете образ, запустите контейнер, а потім опишете застосунок і базу даних в одному файлі Compose. Це перший крок до сучасного розгортання.

## Мета

Навчитися писати Dockerfile для Node.js-застосунку, збирати образ, запускати контейнер із прокиданням порту та змінними оточення, використовувати Docker Compose.

Після заняття ви повинні вміти:

- писати Dockerfile для Node.js;
- збирати образ і запускати контейнер;
- прокидати порти та передавати змінні оточення;
- використовувати .dockerignore;
- описувати кілька сервісів у docker-compose.yml;

## Обладнання та програмне забезпечення

Visual Studio Code, Node.js 20 LTS і новіший (перевірка: `node -v`), npm, сучасний браузер (Chrome або Firefox), Git. Усі приклади працюють локально, без реєстрації в зовнішніх сервісах.

## Теоретична частина

**Образ** це незмінний шаблон з файлової системи та команди запуску, а **контейнер** це запущений екземпляр образу. Образ складається з шарів; Docker кешує шари, тому порядок інструкцій впливає на швидкість збірки: спершу копіюють `package.json` та встановлюють залежності (змінюється рідко), потім код (змінюється часто). **Compose** описує кілька контейнерів та їхні зв'язки одним файлом.

## Хід роботи

### Крок 1. Створіть застосунок

Створіть каталог `app`, виконайте `npm init -y` і `npm i express`. У `server.js` створіть вебсервер, що читає порт зі змінної оточення.

```js
const express = require("express");
const app = express();
const port = process.env.PORT || 3000;
app.get("/", (req, res) => res.send("Привіт із контейнера!"));
app.get("/health", (req, res) => res.json({ status: "ok" }));
app.listen(port, () => console.log(`Listening on ${port}`));
```

### Крок 2. Напишіть Dockerfile та .dockerignore

Інструкція `FROM` обирає базовий образ, `WORKDIR` задає робочий каталог, `COPY` копіює файли, `RUN` виконується при збірці, `CMD` запускається при старті контейнера. У `.dockerignore` перелічіть, що не потрібно потрапляти в образ (особливо `node_modules`).

```dockerfile
# Dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]

# .dockerignore
node_modules
.git
npm-debug.log
```

### Крок 3. Зберіть образ

Виконайте команду збірки, потім перегляньте список образів. Запишіть розмір образу.

```bash
docker build -t hello-app .
docker images hello-app
```

### Крок 4. Запустіть контейнер

Параметр `-p 8080:3000` прокидає порт 3000 контейнера на порт 8080 вашого комп'ютера, `-e` передає змінну оточення, `-d` запускає у фоні.

```bash
docker run -d --name hello -p 8080:3000 -e PORT=3000 hello-app
curl http://localhost:8080
curl http://localhost:8080/health
docker logs hello
docker ps
```

### Крок 5. Опишіть застосунок у Compose

Створіть `docker-compose.yml`, де застосунок залежить від бази Redis; сервіси знаходять один одного за іменами.

```yaml
services:
  web:
    build: .
    ports:
      - "8080:3000"
    environment:
      - PORT=3000
      - REDIS_HOST=cache
    depends_on:
      - cache
  cache:
    image: redis:7-alpine
    volumes:
      - cache-data:/data
volumes:
  cache-data:
```

### Крок 6. Запустіть і зупиніть усе разом

`docker compose up -d` створить мережу, том і обидва контейнери. Перевірте `docker compose ps`. Зупиніть командою `docker compose down`; ключ `-v` додатково видалить том.

```bash
docker compose up -d --build
docker compose ps
docker compose down
```

## Завдання для самостійного виконання

Додайте до Dockerfile інструкцію `HEALTHCHECK` (виклик `/health` кожні 30 секунд) і перегляньте статус контейнера в `docker ps` (стовпець STATUS покаже `healthy`). Поясніть, навіщо оркестраторам така перевірка.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базового завдання |
|---|---|
| 1 | порт 8080 → 3000, відповідь «Привіт» |
| 2 | образ `node:20-slim` замість alpine, порівняти розмір |
| 3 | додати маршрут `/time`, що повертає поточний час |
| 4 | багатоетапна збірка (multi-stage) для зменшення образу |
| 5 | зберігати лічильник відвідувань у томі |

## Типові помилки

- Копіювати `node_modules` у образ (відсутній `.dockerignore`).
- Копіювати весь код до встановлення залежностей: кеш шарів не працює.
- Забути про прокидання порту (`-p`).
- Слухати `localhost` усередині контейнера замість `0.0.0.0` (для Express це не проблема, для деяких серверів так).
- Зберігати секрети в образі.
