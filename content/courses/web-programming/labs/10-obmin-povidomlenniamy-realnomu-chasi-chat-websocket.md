# Обмін повідомленнями в реальному часі: чат на WebSocket

> [!abstract] Пов'язана лекція
> [[courses/web-programming/lectures/08-node-js-ta-express-js-osnovy|Лекція 8. Node.js та Express.js - основи]], [[courses/web-programming/lectures/03-dom-podii-ta-asynkhronnist|Лекція 3. DOM, події та асинхронність]]. Ви створите простий чат, у якому повідомлення з'являються в усіх клієнтів миттєво, без оновлення сторінки.

## Навіщо ця робота

Звичайний вебзапит працює за схемою «клієнт питає, сервер відповідає». Але чат, біржові котирування чи спільний редактор потребують протилежного: сервер сам має повідомляти клієнтів про зміни. Опитування «чи є щось нове?» кожну секунду створює марне навантаження. WebSocket розв'язує це: після короткого початкового «рукостискання» з'єднання залишається відкритим, і обидві сторони надсилають повідомлення в будь-який момент.

Ви створите сервер на Node.js з бібліотекою `ws` і веб-клієнт на чистому JavaScript, а потім відкриєте кілька вкладок і переконаєтесь, що вони спілкуються одна з одною.

## Мета

Навчитися створювати WebSocket-сервер на Node.js, підключати до нього браузерного клієнта, розсилати повідомлення всім підключеним і обробляти відключення.

Після заняття ви повинні вміти:

- створювати WebSocket-сервер за допомогою ws;
- підключатися до сервера з браузера;
- розсилати повідомлення всім клієнтам;
- кодувати повідомлення у форматі JSON;
- обробляти відключення й помилки;

## Обладнання та програмне забезпечення

Visual Studio Code, Node.js 20 LTS і новіший (перевірка: `node -v`), npm, сучасний браузер (Chrome або Firefox), Git. Усі приклади працюють локально, без реєстрації в зовнішніх сервісах.

## Теоретична частина

**Рукостискання.** Клієнт надсилає звичайний HTTP-запит із заголовком `Upgrade: websocket`; сервер відповідає кодом 101, і з цього моменту TCP-з'єднання використовується за протоколом WebSocket. **Події клієнта** (`WebSocket` у браузері): `open`, `message`, `close`, `error`. Для передавання складних даних їх серіалізують у JSON (`JSON.stringify` / `JSON.parse`). Повідомлення від користувачів слід **екранувати** при виведенні (використовувати `textContent`, а не `innerHTML`), інакше можлива XSS-атака.

## Хід роботи

### Крок 1. Створіть проєкт

Ініціалізуйте проєкт і встановіть бібліотеку `ws`.

```bash
mkdir chat && cd chat
npm init -y
npm install ws
```

### Крок 2. Напишіть сервер

Файл `server.js` приймає з'єднання, а на кожне отримане повідомлення розсилає його всім відкритим клієнтам. Ім'я користувача передається в самому повідомленні.

```js
const { WebSocketServer, WebSocket } = require("ws");
const wss = new WebSocketServer({ port: 8081 });

wss.on("connection", (socket) => {
  console.log("клієнтів:", wss.clients.size);
  socket.on("message", (data) => {
    let msg;
    try { msg = JSON.parse(data.toString()); } catch { return; }
    const out = JSON.stringify({ user: String(msg.user).slice(0, 20), text: String(msg.text).slice(0, 500), at: Date.now() });
    for (const client of wss.clients) {
      if (client.readyState === WebSocket.OPEN) client.send(out);
    }
  });
  socket.on("close", () => console.log("клієнтів:", wss.clients.size));
});
console.log("WebSocket-сервер на ws://localhost:8081");
```

### Крок 3. Створіть клієнт

Файл `index.html` містить поле імені, список повідомлень і форму. Текст вставляйте через `textContent`.

```html
<!doctype html>
<html lang="uk">
<head><meta charset="utf-8"><title>Чат</title></head>
<body>
  <input id="user" placeholder="Ваше ім'я" value="Гість">
  <ul id="log"></ul>
  <form id="form"><input id="text" autocomplete="off" required><button>Надіслати</button></form>
  <script>
    const ws = new WebSocket("ws://localhost:8081");
    const log = document.getElementById("log");
    ws.addEventListener("message", (e) => {
      const m = JSON.parse(e.data);
      const li = document.createElement("li");
      li.textContent = new Date(m.at).toLocaleTimeString() + " " + m.user + ": " + m.text;
      log.appendChild(li);
    });
    ws.addEventListener("close", () => log.append("З'єднання закрито"));
    document.getElementById("form").addEventListener("submit", (e) => {
      e.preventDefault();
      const text = document.getElementById("text");
      ws.send(JSON.stringify({ user: document.getElementById("user").value, text: text.value }));
      text.value = "";
    });
  </script>
</body>
</html>
```

### Крок 4. Запустіть і перевірте

Запустіть сервер `node server.js`, відкрийте `index.html` у двох вкладках браузера, введіть різні імена й надішліть кілька повідомлень. Вони мають з'являтися в обох вкладках миттєво. Закрийте одну вкладку й подивіться, як змінився лічильник клієнтів у консолі.

### Крок 5. Проаналізуйте мережевий обмін

Відкрийте DevTools, вкладку Network, фільтр WS, оберіть з'єднання й вкладку Messages. Ви побачите кожне повідомлення зі стрілками «вгору» (надіслано) і «вниз» (отримано). У заголовках знайдіть `101 Switching Protocols` та `Upgrade: websocket`.

> [!tip] Саме ця вкладка допомагає налагоджувати WebSocket: видно, що реально пішло в мережу.

## Завдання для самостійного виконання

Додайте відображення кількості підключених користувачів: сервер надсилає всім службове повідомлення `{type: "count", n: ...}` при кожному підключенні й відключенні, а клієнт показує його поруч із заголовком. Продумайте, як відрізняти службові повідомлення від звичайних.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базового завдання |
|---|---|
| 1 | чат із полем імені |
| 2 | кімнати: клієнт обирає кімнату, розсилання лише в ній |
| 3 | індикатор «друкує…» |
| 4 | історія останніх 20 повідомлень для нових клієнтів |
| 5 | обмеження частоти повідомлень (не більше 5 за 10 секунд) |

## Типові помилки

- Вставляти текст користувача через `innerHTML` (XSS).
- Не перевіряти `readyState` перед `send`.
- Не обробляти некоректний JSON: сервер падає.
- Не обмежувати розмір повідомлення.
- Забувати, що через HTTPS-сторінку потрібно використовувати `wss://`.
