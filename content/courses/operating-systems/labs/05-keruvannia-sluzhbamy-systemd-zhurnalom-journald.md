# Керування службами systemd і журналом journald

> [!abstract] Пов'язана лекція
> [[courses/operating-systems/lectures/01-vstup-do-operatsiinykh-system|Лекція 1. Вступ до операційних систем]], [[courses/operating-systems/lectures/09-vvedennia-vyvedennia-ta-draivery|Лекція 9. Введення-виведення та драйвери]]. Ви створите власну службу, налаштуєте її автозапуск і навчитеся аналізувати її журнал.

## Навіщо ця робота

Сервер корисний тоді, коли потрібні програми працюють без участі людини: стартують під час завантаження, перезапускаються після збою, записують журнал. У сучасних дистрибутивах Linux це робить системний менеджер systemd. Усе, що ви колись запускали через `service` чи `/etc/init.d`, тепер описується простим файлом-одиницею (unit).

Ви напишете невелику службу, налаштуєте її автоматичний перезапуск, змоделюєте збій і прочитаєте журнал. Це навичка, яка потрібна кожному, хто розгортає програми на сервері.

## Мета

Навчитися створювати й налаштовувати службу systemd, керувати нею командою systemctl, налаштовувати політику перезапуску та аналізувати журнал командою journalctl.

Після заняття ви повинні вміти:

- створювати файл unit для власної служби;
- запускати, зупиняти й вмикати службу в автозавантаження;
- налаштовувати політику перезапуску;
- фільтрувати журнал journalctl за часом, службою й рівнем;

## Обладнання та програмне забезпечення

Комп'ютер або віртуальна машина з Ubuntu 22.04 і новішою (VirtualBox, WSL2). Для роботи потрібні права `sudo`. Перед початком зробіть знімок віртуальної машини: усе, що змінює диски й сервіси, можна буде швидко відкотити.

## Теоретична частина

**Unit-файл** складається з секцій. `[Unit]` описує службу та порядок запуску (`After=network.target`). `[Service]` визначає команду (`ExecStart=`), користувача (`User=`) і політику перезапуску (`Restart=on-failure`). `[Install]` вказує, до якої цілі додавати службу при увімкненні (`WantedBy=multi-user.target`).

**journald** збирає виведення всіх служб у двійковий журнал. `journalctl -u імя` показує записи служби, `-p err` фільтрує за рівнем, `--since "10 min ago"` за часом, `-f` стежить у реальному часі.

## Хід роботи

### Крок 1. Підготуйте програму

Служба буде записувати в журнал повідомлення раз на п'ять секунд. Створіть файл `/usr/local/bin/heartbeat.sh` і зробіть його виконуваним.

```bash
sudo tee /usr/local/bin/heartbeat.sh >/dev/null <<'EOF'
#!/usr/bin/env bash
n=0
while true; do
    n=$((n+1))
    echo "heartbeat $n"
    sleep 5
done
EOF
sudo chmod +x /usr/local/bin/heartbeat.sh
```

### Крок 2. Опишіть службу

Створіть файл `/etc/systemd/system/heartbeat.service`. Параметр `Restart=on-failure` перезапускає службу, якщо вона завершилась із помилкою, а `RestartSec=3` додає паузу.

```ini
[Unit]
Description=Heartbeat demo service
After=network.target

[Service]
ExecStart=/usr/local/bin/heartbeat.sh
Restart=on-failure
RestartSec=3
User=nobody

[Install]
WantedBy=multi-user.target
```

### Крок 3. Запустіть службу

Після зміни unit-файлів завжди виконуйте `sudo systemctl daemon-reload`. Потім запустіть і ввімкніть службу в автозавантаження.

```bash
sudo systemctl daemon-reload
sudo systemctl start heartbeat
sudo systemctl enable heartbeat
systemctl status heartbeat
```

### Крок 4. Прочитайте журнал

Перегляньте записи служби й спробуйте різні фільтри. Ключ `-f` працює як `tail -f`: натисніть Ctrl+C, щоб вийти.

```bash
journalctl -u heartbeat -n 10 --no-pager
journalctl -u heartbeat --since "5 minutes ago"
journalctl -u heartbeat -f
```

### Крок 5. Змоделюйте збій

Знайдіть головний процес і завершіть його сигналом SIGKILL: `sudo kill -9 $(systemctl show -p MainPID --value heartbeat)`. Через кілька секунд виконайте `systemctl status heartbeat`: служба знову працює з новим PID, а журнал містить запис про перезапуск. Спробуйте `sudo systemctl stop heartbeat`: після такої зупинки автоматичного перезапуску не буде, бо вона навмисна.

### Крок 6. Приберіть за собою

Вимкніть і видаліть службу, щоб вона не залишилася у вашій системі.

```bash
sudo systemctl disable --now heartbeat
sudo rm /etc/systemd/system/heartbeat.service
sudo systemctl daemon-reload
```

## Завдання для самостійного виконання

Налаштуйте службу так, щоб вона обмежувала себе: додайте у секцію `[Service]` параметри `MemoryMax=50M` і `NoNewPrivileges=true`. З'ясуйте за `systemctl show heartbeat -p MemoryMax`, що обмеження застосовано, і поясніть, навіщо обмеження на рівні служби.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базового завдання |
|---|---|
| 1 | службу `heartbeat` з інтервалом 5 с |
| 2 | службу, що кожні 10 с записує в журнал навантаження системи |
| 3 | службу з `Restart=always` і порівняння з `on-failure` |
| 4 | таймер `heartbeat.timer` замість нескінченного циклу |
| 5 | службу, що запускається лише після `network-online.target` |

## Типові помилки

- Забути `daemon-reload` після зміни unit-файлу.
- Неправильні права на скрипт: служба не стартує (`status=203/EXEC`).
- Помилки у назві секцій unit-файлу.
- Шукати журнал у `/var/log` замість `journalctl`.
