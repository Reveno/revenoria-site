# Автоматизація адміністрування: сценарії оболонки Bash

> [!abstract] Пов'язана лекція
> [[courses/operating-systems/lectures/01-vstup-do-operatsiinykh-system|Лекція 1. Вступ до операційних систем]], [[courses/operating-systems/lectures/02-protsesy-ta-potoky|Лекція 2. Процеси та потоки]]. Ви напишете сценарій, що збирає показники системи, і навчитеся запускати його за розкладом.

## Навіщо ця робота

Адміністратор, який щоразу вводить ті самі команди вручну, помиляється і втрачає час. Сценарії оболонки дозволяють записати послідовність дій один раз і відтворювати її безпомилково: перевірити диски, зібрати журнали, зробити резервну копію. Bash присутній у кожному Linux, тому сценарій працюватиме будь-де без встановлення додаткових програм.

У роботі ви напишете сценарій моніторингу, у якому є змінні, умови, цикли, функції й обробка помилок, а потім запустите його автоматично кожну хвилину. Це хороша вправа на «системне мислення»: сценарій має працювати без вашої участі, тож мусить сам про все повідомляти.

## Мета

Навчитися писати сценарії Bash із змінними, умовами, циклами та функціями, обробляти аргументи й коди завершення, журналувати результат і запускати сценарії за розкладом через cron.

Після заняття ви повинні вміти:

- писати сценарії зі змінними, умовами та циклами;
- використовувати функції й аргументи командного рядка;
- перевіряти коди завершення команд;
- записувати результати в журнал;
- налаштовувати завдання cron;

## Обладнання та програмне забезпечення

Комп'ютер або віртуальна машина з Ubuntu 22.04 і новішою (VirtualBox, WSL2). Для роботи потрібні права `sudo`. Перед початком зробіть знімок віртуальної машини: усе, що змінює диски й сервіси, можна буде швидко відкотити.

## Теоретична частина

**Структура сценарію.** Перший рядок `#!/usr/bin/env bash` (shebang) вказує інтерпретатор. Рядок `set -euo pipefail` робить сценарій суворішим: `-e` завершує його при першій помилці, `-u` забороняє невизначені змінні, `pipefail` не дозволяє приховати помилку в конвеєрі.

**Коди завершення.** Кожна команда повертає число в змінній `$?`: 0 означає успіх, інше значення помилку. Умови `if` перевіряють саме це.

**cron.** Планувальник завдань читає таблицю з п'яти полів `хвилина година день місяць день_тижня` і команди. Запис `*/5 * * * *` означає «кожні п'ять хвилин».

## Хід роботи

### Крок 1. Створіть каркас сценарію

Створіть каталог `~/lab4` і файл `monitor.sh`. Зробіть його виконуваним командою `chmod u+x monitor.sh`. Перші рядки задають інтерпретатор, суворий режим і змінні.

```bash
#!/usr/bin/env bash
set -euo pipefail
LOG="${HOME}/lab4/monitor.log"
THRESHOLD="${1:-80}"   # поріг заповнення диска, % (аргумент 1, типово 80)
```

### Крок 2. Додайте функції збору показників

Функція складається з імені та тіла у фігурних дужках. Для кожного показника напишіть окрему функцію: так сценарій легше читати й перевіряти.

```bash
disk_usage() { df --output=pcent / | tail -1 | tr -dc '0-9'; }
mem_usage()  { free | awk '/Mem:/ {printf "%d", $3/$2*100}'; }
load_avg()   { cut -d' ' -f1 /proc/loadavg; }
log() { echo "$(date '+%F %T') $*" | tee -a "$LOG"; }
```

### Крок 3. Додайте перевірки й попередження

Зберіть показники та порівняйте з порогом. Оператор `-gt` порівнює числа. Попередження пишіть у журнал з позначкою WARN, а при проблемі завершуйте сценарій ненульовим кодом.

```bash
D=$(disk_usage); M=$(mem_usage); L=$(load_avg)
log "disk=${D}% mem=${M}% load=${L}"
if [ "$D" -gt "$THRESHOLD" ]; then
    log "WARN: диск заповнено більше ніж на ${THRESHOLD}%"
    exit 2
fi
```

### Крок 4. Перевірте обробку помилок

Запустіть сценарій з нечисловим аргументом (`./monitor.sh abc`). Без перевірки Bash повідомить про помилку порівняння. Додайте на початок перевірку `echo "$THRESHOLD" | grep -qE '^[0-9]+$' || { echo "поріг має бути числом" >&2; exit 1; }` і повторіть: тепер повідомлення зрозуміле, а код завершення 1.

> [!tip] Повідомлення про помилки виводьте у stderr (`>&2`), а результат у stdout: так їх можна розділяти перенаправленням.

### Крок 5. Налаштуйте запуск за розкладом

Відкрийте таблицю cron командою `crontab -e` і додайте запис, що запускає сценарій щохвилини. Шляхи в cron мають бути абсолютними, бо його середовище мінімальне.

```bash
* * * * * /home/ВАШ_КОРИСТУВАЧ/lab4/monitor.sh 90 >> /home/ВАШ_КОРИСТУВАЧ/lab4/cron.out 2>&1
```

### Крок 6. Перегляньте результат

Зачекайте кілька хвилин і виведіть журнал: `tail -n 5 ~/lab4/monitor.log`. Переконайтеся, що записи з'являються щохвилини. Потім видаліть завдання (`crontab -e`, видалити рядок), щоб воно не працювало вічно.

## Завдання для самостійного виконання

Додайте до сценарію параметр `-v` (докладний вивід) за допомогою `getopts` і перевірку наявності обов'язкових утиліт (`command -v awk >/dev/null || ...`). Поясніть, чому перевірка залежностей на початку краща за помилку посеред роботи.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базового завдання |
|---|---|
| 1 | контролювати розділ `/home`, поріг 70 % |
| 2 | додатково контролювати кількість процесів (`ps -e | wc -l`) |
| 3 | записувати журнал у `/tmp` і ротувати файл при розмірі понад 1 МБ |
| 4 | надсилати попередження в `logger` (системний журнал) |
| 5 | виводити результат у форматі CSV: час, диск, пам'ять, навантаження |

## Типові помилки

- Не зробити файл виконуваним (`Permission denied`).
- Використати відносні шляхи в cron.
- Не обернути змінні в лапки: імена з пробілами ламають команди.
- Не відокремити stderr від stdout.
- Залишити завдання cron після завершення роботи.

## Контрольні питання

2. Як у Bash перевірити, що команда завершилась успішно?
3. Що означає запис `*/5 9-17 * * 1-5` у cron?

## Вимоги до звіту

Звіт подається без титульного листа й містить: тему й мету; повний перелік виконаних команд або код; скриншоти ключових кроків (із видимим запрошенням терміналу або вікном редактора); відповіді на контрольні питання; висновки.
