# Логічні томи LVM і програмний RAID

> [!abstract] Пов'язана лекція
> [[courses/operating-systems/lectures/08-failovi-systemy|Лекція 8. Файлові системи]], [[courses/operating-systems/lectures/09-vvedennia-vyvedennia-ta-draivery|Лекція 9. Введення-виведення та драйвери]]. Ви створите гнучке сховище з кількох віртуальних дисків і дослідите стійкість RAID-масиву до відмови.

## Навіщо ця робота

Класичні розділи мають недолік: розмір задається раз і назавжди. Якщо раптом на розділі закінчилося місце, довелося б переносити дані. LVM додає між диском і файловою системою гнучкий шар, у якому тому можна збільшувати «на льоту», а кілька дисків об'єднувати в один пул. RAID вирішує іншу проблему: що робити, коли диск виходить з ладу.

Усі експерименти ви проведете на «дисках», створених із звичайних файлів (loop-пристрої), тому реального обладнання не потрібно й нічого не загрожує вашим даним.

## Мета

Навчитися створювати фізичні томи, групи та логічні томи LVM, збільшувати том без зупинки, створювати RAID 1 засобами mdadm та імітувати відмову диска.

Після заняття ви повинні вміти:

- створювати loop-пристрої із файлів;
- налаштовувати PV, VG, LV;
- збільшувати логічний том і файлову систему;
- створювати масив RAID 1 та аналізувати його стан;
- відновлювати масив після відмови диска;

## Обладнання та програмне забезпечення

Комп'ютер або віртуальна машина з Ubuntu 22.04 і новішою (VirtualBox, WSL2). Для роботи потрібні права `sudo`. Перед початком зробіть знімок віртуальної машини: усе, що змінює диски й сервіси, можна буде швидко відкотити.

## Теоретична частина

**LVM.** Фізичні томи (PV) це диски чи розділи, віддані під керування LVM. Група томів (VG) об'єднує PV в єдиний пул. Логічні томи (LV) нарізаються з пулу; їх розмір можна змінювати, а файлову систему розширювати разом із ними.

**RAID.** RAID 0 чергує дані між дисками (швидкість, але без стійкості), RAID 1 дзеркалить (стійкість до відмови одного диска), RAID 5 використовує паритет (стійкість до відмови одного диска при економнішому використанні місця). Програмний RAID у Linux створює утиліта `mdadm`.

## Хід роботи

### Крок 1. Створіть віртуальні диски

Створіть три файли по 200 МБ і підключіть їх як блокові пристрої. Команда `losetup -f --show` повертає ім'я вільного пристрою.

```bash
mkdir -p ~/lab6 && cd ~/lab6
for i in 0 1 2; do truncate -s 200M disk$i.img; sudo losetup -f --show disk$i.img; done
lsblk | grep loop
```

### Крок 2. Створіть PV та VG

Перші два пристрої (скажімо, `/dev/loop10` і `/dev/loop11`; підставте свої імена) віддайте під LVM і об'єднайте в групу `vgdata`.

```bash
sudo apt install -y lvm2 mdadm
sudo pvcreate /dev/loop10 /dev/loop11
sudo vgcreate vgdata /dev/loop10 /dev/loop11
sudo vgs
```

### Крок 3. Створіть логічні томи й файлові системи

Створіть том `lvweb` на 250 МБ (він займе місце на двох дисках, бо один має лише 200 МБ), відформатуйте та змонтуйте.

```bash
sudo lvcreate -L 250M -n lvweb vgdata
sudo mkfs.ext4 /dev/vgdata/lvweb
sudo mkdir -p /mnt/web && sudo mount /dev/vgdata/lvweb /mnt/web
df -h /mnt/web
```

![[attachments/os-lab06-step3.svg|820]]
*Крок 3. Група vgdata і логічний том lvweb. Вигляд терміналу Linux (приклад очікуваного виводу; ваші значення можуть відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 4. Збільште том на ходу

Імітуйте нестачу місця: додайте диск у групу і розширте том разом із файловою системою (ключ `-r`), не розмонтовуючи.

```bash
sudo pvcreate /dev/loop12
sudo vgextend vgdata /dev/loop12
sudo lvextend -r -L +200M /dev/vgdata/lvweb
df -h /mnt/web
```

> [!tip] Ключ `-r` (resizefs) одночасно розширює й файлову систему. Без нього том стане більшим, а місця в каталозі не побільшає.

### Крок 5. Створіть RAID 1

Для цього кроку створіть ще два файли по 100 МБ, підключіть їх як loop-пристрої (`/dev/loopA`, `/dev/loopB`) і об'єднайте в дзеркальний масив.

```bash
for i in 3 4; do truncate -s 100M disk$i.img; sudo losetup -f --show disk$i.img; done
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/loop13 /dev/loop14
sudo mkfs.ext4 /dev/md0 && sudo mkdir -p /mnt/raid && sudo mount /dev/md0 /mnt/raid
cat /proc/mdstat
```

![[attachments/os-lab06-step5.svg|820]]
*Крок 5. Масив RAID 1 у стані [UU] (обидва диски працюють). Вигляд терміналу Linux (приклад очікуваного виводу; ваші значення можуть відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 6. Імітуйте відмову диска

Запишіть тестовий файл у `/mnt/raid`, потім позначте один диск як несправний і видаліть із масиву. Дані мають лишитися доступними. Після цього додайте новий диск і дочекайтеся відновлення.

```bash
echo "важливі дані" | sudo tee /mnt/raid/data.txt
sudo mdadm /dev/md0 --fail /dev/loop14
sudo mdadm /dev/md0 --remove /dev/loop14
cat /mnt/raid/data.txt
cat /proc/mdstat
# заміна: додаємо чистий диск
sudo mdadm /dev/md0 --add /dev/loop14
```

![[attachments/os-lab06-step6.svg|820]]
*Крок 6. Деградований масив [U_] і відновлення після заміни диска. Вигляд терміналу Linux (приклад очікуваного виводу; ваші значення можуть відрізнятися). Джерело: власна ілюстрація автора курсу, для цього конспекту.*

### Крок 7. Приберіть за собою

Розмонтуйте, видаліть структури й від'єднайте пристрої, щоб не залишити артефактів.

```bash
sudo umount /mnt/web /mnt/raid
sudo lvremove -y vgdata && sudo vgremove vgdata
sudo mdadm --stop /dev/md0
sudo losetup -D
```

## Завдання для самостійного виконання

Створіть RAID 5 на трьох loop-пристроях по 100 МБ. Обчисліть очікуваний корисний обсяг (для N дисків це (N-1) розміру диска), перевірте командою `lsblk` і порівняйте з RAID 1 з двох дисків за надлишковістю та стійкістю.

## Індивідуальні завдання (варіанти)

Варіант обирається за порядковим номером у списку групи (якщо номер більший за 5, від нього віднімають 5 до отримання числа від 1 до 5).

| № | Зміни до базового завдання |
|---|---|
| 1 | група з двох PV, том 250 МБ, розширити на 200 МБ |
| 2 | два томи: 150 МБ (ext4) і 100 МБ (xfs) |
| 3 | RAID 1 з трьох дисків (дві копії + запасний) |
| 4 | знімок (`lvcreate -s`) тому та відновлення файла |
| 5 | RAID 0 з двох дисків і порівняння швидкості запису `dd` |

## Типові помилки

- Використовувати реальний диск замість loop-пристрою.
- Розширити LV без `-r`.
- Видалити VG, не розмонтувавши тому.
- Помилково використати RAID замість резервного копіювання.
