# Порівняльний аналіз сучасних операційних систем за заданими критеріями

> [!abstract] Пов'язана лекція
> [[courses/operating-systems/lectures/12-suchasni-operatsiini-systemy|Лекція 12. Сучасні операційні системи]]. Робота формує вміння порівнювати сучасні операційні системи за критеріями.

## Навіщо ця робота

Вибір операційної системи це інженерне рішення, яке впливає на вартість, безпеку й підтримку на роки. Досвідчений фахівець не каже «Linux кращий» чи «Windows зручніший», а порівнює за критеріями: для якого завдання, яке обладнання, кому підтримувати, які вимоги до безпеки.

У роботі ви складете порівняльну таблицю трьох систем різних класів і обґрунтуєте вибір для конкретного сценарію. Тут головне вміння аргументувати, а не знання фактів.

## Мета

Навчитися порівнювати операційні системи за заданими критеріями, визначати архітектуру ядра та модель розмежування доступу й обґрунтовувати вибір.

Після заняття ви повинні вміти:

- вибирати критерії порівняння;
- розрізняти монолітне, мікроядерне та гібридне ядра;
- описувати моделі розмежування доступу;
- обґрунтовувати вибір ОС для сценарію;

## Обладнання та програмне забезпечення

- Персональний комп'ютер з доступом до мережі Інтернет, доступ до документації виробників.

Усі приклади розраховано на Ubuntu 22.04 або новішу у віртуальній машині (VirtualBox або WSL2). Працюйте від звичайного користувача; `sudo` потрібен лише там, де це вказано. Не виконуйте експериментів на робочій системі, де є важливі дані: усе, що змінює розділи, права чи ядро, робіть у віртуальній машині, зробивши знімок стану перед початком.

## Теоретична частина

Порівнювати операційні системи коректно лише за визначеними критеріями та під конкретну задачу. Основні критерії: архітектура ядра, модель розмежування доступу, механізми керування пам'яттю, підтримка апаратного забезпечення, засоби адміністрування й автоматизації, модель ліцензування, тривалість підтримки, наявність фахівців. Окремий клас становлять системи реального часу, для яких визначальним є не середня швидкодія, а гарантована верхня межа часу реакції.

Критерії порівняння: призначення, архітектура ядра, планувальник, керування пам'яттю, файлові системи, модель безпеки, підтримка обладнання, ліцензія та вартість, екосистема, цикл підтримки. Приклади: Linux (монолітне ядро з модулями), Windows (гібридне), macOS (гібридне, XNU), FreeBSD (монолітне), QNX/FreeRTOS (реального часу), Android (ядро Linux із власною екосистемою).

## Хід роботи

Нижче кожен крок із методички доповнено поясненням: що саме робити, як і навіщо. Не пропускайте пояснень: вони вказують, на що звертати увагу й чого очікувати.

### Крок 1. Оберіть три системи: настільну, серверну та мобільну або реального часу

Оберіть три системи: наприклад, Ubuntu (сервер), Windows 11 (настільна) і Android або FreeRTOS (мобільна чи реального часу). Обґрунтуйте вибір одним реченням кожну.

### Крок 2. Складіть таблицю порівняння за восьма критеріями з теоретичної частини

Складіть таблицю за вісьмома критеріями. Для кожної комірки вказуйте перевірний факт із документації й посилання на неї, а не загальні слова.

### Крок 3. Для кожної системи зазначте архітектуру ядра та обґрунтуйте віднесення

Для кожної системи вкажіть тип ядра і поясніть, що це означає для надійності (збій драйвера у монолітному ядрі може обвалити систему) та швидкодії.

### Крок 4. Опишіть модель розмежування доступу кожної системи

Опишіть модель доступу: Linux (дискреційна + SELinux/AppArmor), Windows (ACL, UAC, RBAC), Android (пісочниця застосунків, дозволи).

### Крок 5. Сформулюйте по два сценарії, у яких кожна система є найкращим вибором

Для кожної системи придумайте по два сценарії, де вона найкраща (з аргументами).

### Крок 6. Наведіть приклад задачі, для якої жодна з обраних систем не підходить, і поясніть чому

Наведіть задачу, для якої жодна з трьох не підходить (наприклад, керування кардіостимулятором: потрібна сертифікована ОС реального часу), і поясніть чому.

## Типові помилки

- Порівнювати за враженнями без джерел.
- Обирати за популярністю, а не за вимогами.
- Ігнорувати вартість підтримки.
- Змішувати ядро та дистрибутив.

## Контрольні питання

1. Чому питання «яка система краща» некоректне без уточнення задачі?
2. Чим монолітне ядро відрізняється від гібридного?
3. Які критерії важливі для серверної системи й неважливі для настільної?
4. Чому система загального призначення не придатна для жорсткого реального часу?
5. Які чинники, окрім технічних, впливають на вибір системи в організації?

## Вимоги до звіту

Звіт подається без титульного листа й містить:

1. Тему та мету роботи.
2. Умову завдання (номер варіанта).
3. Хід виконання роботи зі скриншотами ключових кроків.
4. Результати виконання завдань (вихідний код, схеми, конфігурації або протоколи вимірювань, залежно від роботи).
5. Відповіді на контрольні питання.
6. Висновки.

Скриншоти мають показувати термінал із запрошенням (ім'я користувача, ім'я машини, поточний каталог) і виведення команд повністю, а не обрізаним. Текстові результати (таблиці, виведення програм) краще вставляти текстом у блоках коду: це дозволяє перевірити їх пошуком. Код програм додавайте у звіт повністю, з коментарями.
